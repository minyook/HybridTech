# iPhone에서 같은 Wi-Fi로 시험하기

최종 갱신: 2026-10-20. 앱·AI·PWA의 HTTPS 시험을 위한 개발 전용 안내입니다. 실제 iPhone의 인증서 설치와 Safari 실행은 사용자가 직접 확인해야 합니다.

## PC에서 실행

PC와 iPhone을 같은 Wi-Fi에 연결합니다. Node.js 24.15 이상과 OpenSSL이 필요하며, Windows에서는 설치된 Git for Windows의 `C:/Program Files/Git/usr/bin/openssl.exe`도 자동으로 찾습니다.

저장소 루트에서 실행합니다.

```powershell
cd web
npm.cmd run iphone:test
```

이 명령은 최신 프로덕션/PWA 파일을 빌드한 뒤 현재 PC의 사설 IPv4 주소에 두 서버를 엽니다. 기존 4173 HTTP 미리보기와 5174 개발 서버는 그대로 사용할 수 있습니다.

| 출력 주소 | 역할 |
|---|---|
| `http://<PC-IP>:4172/` | 인증서 설치 안내·공개 인증서 프로파일 다운로드 |
| `https://<PC-IP>:4174/` | 실제 웹/PWA·모델·작업 API 시험 |

**주소와 포트의 HTTP/HTTPS를 구분합니다.** `https://<PC-IP>:4173/`은 HTTP 서버에 TLS 연결을 시도하므로 보안 연결 오류가 납니다. `http://<PC-IP>:4173/`도 인증서 검증·Cache API·WebGPU·서비스 워커가 필요한 전체 앱 시험에는 적합하지 않습니다. HTTP 주소의 최초 문서 로딩 단계에서도 오류가 날 수 있습니다.

터미널에 출력된 실제 주소를 사용합니다. 사설 IP가 여러 개면 `FIELDGUARD_TEST_HOST`에 이 PC의 Wi-Fi IPv4 주소를 지정한 뒤 실행할 수 있습니다. 인터넷 공개 터널·포트 포워딩·클라우드 배포는 이 명령에 포함하지 않습니다.

## iPhone에서 직접 진행

1. Safari에서 `http://<PC-IP>:4172/`을 엽니다. 이 설치 안내 주소는 **http**입니다.
2. **개발용 인증서 다운로드**를 누릅니다. 프로파일 이름은 **Field Guard Local Test CA**입니다.
3. 설정 → **프로파일이 다운로드됨 → 설치**로 이동합니다. 메뉴가 보이지 않으면 일반 → VPN 및 기기 관리에서 다운로드한 프로파일을 선택합니다. 암호 입력과 설치는 사용자가 직접 진행합니다.
4. 설정 → 일반 → 정보 → **인증서 신뢰 설정**에서 **Field Guard Local Test CA**의 전체 신뢰를 켭니다. 프로파일 설치만으로는 SSL/TLS 신뢰가 자동 활성화되지 않습니다.
5. 설치 안내로 돌아와 **Field Guard 열기**를 누르거나 `https://<PC-IP>:4174/`을 엽니다. 이 앱 주소는 **https**입니다.
6. Safari 공유 → **홈 화면에 추가**로 설치하고 홈 화면 아이콘으로 다시 실행합니다. 그 화면에서 문서·모델을 준비합니다.

Apple 공식 안내: [프로파일 설치](https://support.apple.com/ko-kr/102400), [수동 인증서의 SSL/TLS 신뢰](https://support.apple.com/ko-kr/102390), [홈 화면 웹 앱 추가](https://support.apple.com/ko-kr/guide/iphone/iphea86e5236/ios).

이 프로파일에는 공개 개발용 CA 인증서 하나만 들어 있습니다. 해당 CA를 신뢰하면 이 PC가 발급한 서버 인증서를 iPhone이 신뢰합니다. PC의 개인키는 다운로드되지 않습니다. 테스트가 끝나면 설정 → 일반 → VPN 및 기기 관리에서 프로파일을 제거할 수 있습니다. PC의 Windows 인증서 저장소에는 자동 등록하지 않습니다.

## iPhone AI의 별도 지원 조건

현재 기기 내 Gemma는 LiteRT-LM WebGPU 경로를 사용합니다. HTTPS로 웹이 열려도 WebGPU가 없는 브라우저에서는 모델 다운로드와 AI 실행을 진행하지 않습니다.

- iPhone·iPad의 정식 WebGPU 지원은 **iOS·iPadOS 26부터**입니다. iOS 18.6.2에서는 기본 Safari에서 현재 AI를 실행할 수 없습니다. 사용자 보고로 iPhone 13 Pro / iOS 18.6.2의 해당 차단 상황을 확인했으며, 실제 기기의 AI 실행 성공을 확인한 것은 아닙니다.
- **iPhone 13 Pro는 iOS 26 지원 기종**입니다. 설정 → 일반 → 소프트웨어 업데이트에서 지원되는 최신 정식 버전으로 업데이트한 뒤 Safari와 홈 화면 앱을 완전히 닫고 다시 시험합니다.
- 실제 판정은 운영체제 이름이나 사용자 에이전트의 숫자로 차단하지 않고 `isSecureContext`, WebGPU, Worker 기능을 확인합니다. Safari의 사용자 에이전트가 실제 iOS 버전과 다를 수 있어 표시 문자열을 실행 가능 여부로 신뢰하지 않습니다.
- 설정은 보안 연결·AI 그래픽 기능·백그라운드 실행의 실패 원인을 구분해 표시합니다. 미지원 환경에서 약 2GB 모델을 다운로드하도록 유도하지 않습니다.
- iOS 업데이트와 기본 기능 검사 통과만으로 실제 Gemma 실행을 보장하지 않습니다. 기기의 사용 가능한 메모리·GPU와 모델 적재·첫 답변을 별도로 시험해야 합니다. 문서·PDF·작업 요청/감독관 승인은 이 AI 기능과 분리됩니다.

공식 근거: [WebKit의 Safari 26 WebGPU 지원](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/#webgpu), [Apple iOS 26 지원 기종과 업데이트](https://support.apple.com/ko-kr/123705). 실행 조건 구현은 `web/src/ai/capabilities.ts`입니다.

## 모델 준비 중 페이지가 반복 종료될 때

이 절차는 모델 준비 중과 질문 중 종료에 모두 적용합니다. 2026-10-19 사용자 보고: iPhone 13 Pro / iOS 27.0.1에서 다운로드 완료 후 모델 준비 중, 이후 질문을 보낸 뒤 ‘문제가 반복적으로 발생했습니다’ 화면이 나타났습니다. 질문 중 오류는 **홈 화면에 추가한 Field Guard 아이콘**에서 발생했다고 확인했습니다. 브라우저 페이지 종료는 확인했지만 원인 로그가 없어 메모리·WASM·GPU 중 정확한 원인을 확정하지 않았습니다. 아래는 저장된 모델을 유지하는 복구 절차이며 해당 기기의 실제 AI 실행 성공을 보장하지 않습니다.

**2026-10-20 추가 보고:** 사용자는 복구 재시도 후에도 설정에서 반복 종료되며 다음 실행에 **‘모델 메모리 적재 완료를 확인하지 못해’**가 표시된다고 확인했습니다. 따라서 아래 복구를 이미 수행한 이 기기에는 추가 반복을 권하지 않습니다. 새 시도의 실제 저장 문맥·엔진 로그·시스템 종료 로그는 아직 수집하지 못했습니다. 메모리 압박 가능성은 있으나 이 문구는 적재 완료 미확인 표시이며 OOM을 확정하는 로그는 아닙니다. 모델 준비가 끝나기 전의 실패라 답변 토큰을 늘리는 것으로 해결할 수 있다고 안내하지 않습니다.

**이후 전달된 당일 로그:** 10/20 10:43:52·iOS 27.0.1 Jetsam 기록에서 WebKit WebContent의 `highwater` 종료를 확인했습니다. 구체적인 JS/WASM 할당 위치나 URL은 로그만으로 특정하지 않습니다. 새 수정은 같은 E2B 파일을 필요한 구간에서 직접 읽어 SDK 중간 캐시를 피합니다. [분석·구조·검증 한계](webapp/IPHONE_MEMORY_ANALYSIS.md)를 참고하세요. 기존 설정과 같은 코드를 반복 시험하는 것이 아니라 아래 절차로 **새 읽기 경로가 반영됐는지 확인한 뒤** 한 번 시험합니다.

**홈 화면 아이콘에서 실행한 경우**

1. PC의 HTTPS 시험 서버를 켜 둡니다. Safari의 Field Guard 탭과 홈 화면 앱을 앱 전환기에서 완전히 닫습니다. 아이콘을 삭제하거나 웹 사이트 데이터를 지우지 않습니다.
2. 홈 화면의 기존 **Field Guard 아이콘**을 한 번 열어 업데이트를 받습니다. 잠시 기다린 뒤 앱을 완전히 닫고 다시 엽니다. 서비스 워커 업데이트는 구형 화면이 모두 닫힌 뒤 적용됩니다. 설정에 **‘저장 파일을 필요한 부분씩 읽어 준비해요’**가 보이는지 확인합니다. 이전 ‘메모리 절약 방식으로 실행해요’ 문구만 보이거나 복구 안내가 4,096·512라면 구형 화면이므로 한 번 더 닫고 엽니다.
3. 새 버전은 중단 표시가 남은 홈·질문 화면의 시작을 **설정**으로 안내합니다. 자동 AI 준비는 멈추고 저장된 모델은 유지합니다. 직접 설정을 열어도 됩니다. 다른 문서·PDF 화면은 계속 사용할 수 있습니다.
4. **자동 재시도 중지**와 모델 파일 저장 상태를 확인한 뒤 **문맥을 줄여 다시 준비**를 한 번 누릅니다. 문맥 **2,048·최대 답변 256 토큰**으로 준비가 끝나면 짧은 질문 하나로 시험합니다. 이는 기존 모델을 사용하며 재다운로드가 아닙니다.
5. 같은 종료가 반복되면 다시 준비·질문을 반복하지 않습니다. 앱을 다시 열어 설정의 중단 단계 문구를 확인합니다. 실제 iPhone WebKit/시스템 종료 로그와 실행 경로의 추가 검증이 필요합니다.

**Safari 탭에서 실행한 경우**

모델을 다운로드했던 **같은 Safari·같은 HTTPS 주소**에서 `https://<PC-IP>:4174/api/ai-recovery`를 엽니다. 현재 시험 PC 주소는 `https://192.168.0.31:4174/api/ai-recovery`이며 IP가 바뀌면 터미널의 새 주소를 사용합니다. **자동 재시도를 멈추고 복구 설정 적용 → 설정 화면 다시 열기**를 선택한 뒤 위의 4~5번을 진행합니다. Safari와 홈 화면 앱의 저장소가 분리된 경우 Safari 복구가 홈 화면 앱의 모델·설정에 적용되지 않습니다. 홈 화면 앱의 모델이 Safari에서 보이지 않는다고 다시 다운로드하지 않습니다.

복구 페이지는 앱·모델·WASM을 로드하지 않으며 기존 서비스 워커도 캐시하지 않는 `/api/` 경로로 제공합니다. 사용자 선택 시 준비 중단 표시를 localStorage에 기록하고 해당 주소의 루트 서비스 워커 등록만 해제해 최신 화면을 엽니다. **OPFS 모델·IndexedDB·캐시·대화·서버 작업은 삭제하지 않습니다.** Safari의 ‘웹 사이트 데이터 지우기’로 복구하면 모델까지 사라지므로 이 절차에는 포함하지 않습니다. PC 서버는 켜 두어야 합니다.

iPhone/iPad에서 새 설정의 기본값은 문맥 4,096·답변 512이며 데스크톱은 8,192·1,536입니다. 사용자가 이미 저장한 설정은 유지하고 복구 버튼을 선택한 경우에만 **2,048·256**으로 바꿉니다. Apple 모바일 엔진에는 입력 배치 1·자동 크기 로컬 어텐션 버퍼·가중치 업로드 대기를 적용합니다. 문서 근거는 그대로 전달하며 첫 답변까지 시간이 늘 수 있습니다. 이 설정으로 전체 메모리 한도를 보장하지 않습니다.

### 첫 답변은 되지만 다음 질문에서 종료될 때

2026-10-20 최신 사용자 보고에서는 첫 답변 후 두 번째 질문 **‘심폐소생술 알려줘’**에서 홈 화면 앱이 다시 열리고 **‘답변 토큰 생성 완료를 확인하지 못해’**가 표시됐습니다. 새 사건의 원인 로그는 아직 없으며 앞선 모델 적재 시각의 `highwater` 로그로 같은 원인을 확정하지 않습니다.

새 버전은 iPhone/iPad에서 답변마다 conversation·엔진을 삭제하고 Worker를 종료한 뒤 다음 질문용 엔진 하나를 자동 준비합니다. 준비 중 보낸 질문은 대기 후 처리합니다. 데스크톱은 엔진을 재사용합니다. 모델·대화·토큰 선택은 유지하지만 **질문 사이에 모델 준비 시간이 추가될 수 있습니다.**

1. PC 서버를 켜고 기존 홈 화면 Field Guard 앱을 한 번 열어 업데이트를 받습니다. 같은 주소의 앱·탭을 모두 닫았다가 다시 엽니다. 사이트 데이터나 모델은 지우지 않습니다.
2. 설정에 **‘답변이 끝나면 AI 메모리를 정리하고 다음 질문을 자동으로 준비해요’** 문구가 보이는지 확인합니다. 이전 종료 표시가 남았다면 자기 홈 화면 앱의 복구 선택으로 기존 모델을 준비합니다.
3. 현재 토큰 선택으로 첫 질문을 보냅니다. 답변 완료 후 **‘심폐소생술 알려줘’**를 보내고, 준비 중이면 기다립니다. 이어 세 번째 질문도 처리되는지 확인합니다.
4. 이전 대화가 남는지, 새로고침·다운로드 없이 질문이 이어지는지 확인합니다. 같은 종료가 반복되면 설정의 중단 단계와 새 시각의 Jetsam/WebKit 로그로 비교합니다.

PC의 iPhone 실행 정책 시험과 실제 기기의 연속 사용 성공은 구분합니다. [엔진 수명 설계와 한계](webapp/IPHONE_MEMORY_ANALYSIS.md#첫-답변-후-두-번째-질문-중-종료) · [실행 기록](../web/docs/validation.md).

준비·생성 중 페이지가 종료된 흔적이 남으면 다음 실행에서 자동 초기화를 중지합니다. 새 워커는 **대화 작업 공간 준비 → 질문·문서 입력 처리 → 답변 토큰 생성**을 구분해 저장합니다. 이전 워커의 ‘답변 생성’ 기록만으로는 세부 단계를 알 수 없습니다. 프롬프트나 답변 본문은 이 진단 표시에 저장하지 않습니다. 정상 다운로드와 재접속의 자동 준비는 유지합니다. 같은 저장소의 여러 화면은 Web Locks 지원 시 AI 엔진 하나만 사용합니다. 저장소가 서로 분리된 Safari/홈 화면 앱은 별도로 닫아야 합니다.

2026-10-19 Windows Chromium에서 같은 공식 모델과 iPhone용 엔진 설정으로 문맥 2,048·입력 1,348·생성 256토큰을 처리했습니다. [PC 실행 화면](../web/docs/screenshots/ai-mobile-profile-pc.jpg)이며 iPhone 13 Pro의 실제 성공·메모리 사용량 개선·답변 정확도를 확인한 결과는 아닙니다. [검증 기록](../web/docs/validation.md)을 참고하세요.

### 준비 완료 후 질문 전송에서도 종료가 재발한 현재 상태

사용자는 엔진 교체 수정 뒤에도 **질문 보내기**를 누른 뒤 종료되고 다음 실행의 안내가 **답변 토큰 생성**이라고 확인했습니다. 화면 이동만의 문제로 분류하지 않으며 현재 기기의 생성 안정성은 미해결입니다. 준비 완료·PC 연속 통과만으로 iPhone의 성공을 보장하지 않습니다. 같은 문맥 축소·재다운로드를 계속 반복하지 않습니다.

정상 종료 시 엔진 삭제 뒤 실제 WebGPU 장치 `destroy()`도 명시했습니다. 새 버전 **`apple-gpu-lifecycle-20261020.3`**의 설정에는 **AI 진단 기록 저장** 버튼이 있습니다. 이는 AI를 다시 실행하지 않고 자기 브라우저/PWA의 로컬 기록을 JSON으로 저장합니다. 앞으로의 실행 단계·토큰 설정·WASM 힙 용량·감지된 GPU 오류 종류를 최근 48개까지 포함하며 질문·답변·주소·기기 식별자는 저장/자동 전송하지 않습니다. WASM 용량은 GPU·전체 프로세스의 메모리가 아닙니다. 업데이트 전에 발생한 사건의 메모리를 소급해 제공하지 않습니다.

이번 사건의 정확한 원인을 확인하려면 **이번 종료 시각에 해당하는 새 JetsamEvent 또는 WebKit 진단 파일**이 필요합니다. iPhone 설정 → 개인정보 보호 및 보안 → 분석 및 향상 → 분석 데이터에서 해당 시각의 기록을 확인합니다. 앞선 10:43:52 기록은 이 사건의 직접 증거로 대신하지 않습니다. 이미 종료가 반복되는 기기에는 진단을 위해 무조건 다시 생성하라고 권하지 않습니다. [근거와 수집 범위](webapp/IPHONE_MEMORY_ANALYSIS.md#준비-완료-뒤-질문-전송-시-decode-종료-재발).

## 시험 순서

- 홈·문서 보관함·PDF를 열고 세로/가로 방향, 키보드 표시, 스크롤을 확인합니다.
- iPhone을 작업자, PC를 감독관으로 사용합니다. PC는 `http://localhost:4173/` 미리보기를 함께 실행해도 같은 DB를 사용합니다. 작업 요청 → 감독관 점검 저장 → 직접 승인 → iPhone 승인 수신 → 작업자 투입 → 감독관 결과 수신을 확인합니다.
- 홈 화면 앱의 설정에서 오프라인 파일과 약 2.01GB Gemma 4 E2B 모델을 준비합니다. Safari/WebGPU·기기 메모리 지원을 확인해야 하며, HTTPS 연결만으로 AI 실행 성공을 보장하지 않습니다.
- 준비 후 서버/네트워크를 끊고 문서와 기존 기록의 오프라인 재실행을 확인합니다. 새로운 작업 요청·감독관 승인은 서버 연결이 필요합니다.

## 파일·키·만료와 재실행

| 파일 | 내용 |
|---|---|
| `web/scripts/iphone-test.mjs` | 빌드 후 같은 Wi-Fi용 설치/HTTPS 서버 실행 |
| `web/server/iphone-https.ts` | 사설 IP 선택, 인증서 생성·재사용, 설치 안내·프로파일 |
| `web/tests/iphone-https.test.ts` | TLS 검증·IP 범위·재사용·개인키 비노출 검사 |
| `web/.local/iphone-https/ca-key.pem` | CA 개인키, Git 제외·공유 금지 |
| `web/.local/iphone-https/ca.pem` | 공개 CA 인증서, 30일 만료 |
| `web/.local/iphone-https/server-key.pem` | HTTPS 서버 개인키, Git 제외·공유 금지 |
| `web/.local/iphone-https/server.pem` | 사설 IP·localhost용 서버 인증서, 7일 만료 |

기존 CA와 키를 재사용하므로 서버를 다시 켤 때마다 iPhone에 새 인증서를 설치할 필요가 없습니다. PC IP가 바뀌면 같은 CA로 서버 인증서만 재발급합니다. 키 불일치나 CA 만료 시 자동으로 다른 CA를 신뢰시키지 않고 중지합니다. CA가 만료되면 iPhone의 기존 프로파일을 제거하고 PC의 해당 폴더를 별도로 보관한 뒤 새 인증서를 준비합니다.

서버는 Ctrl+C로 종료합니다. 앱 데이터와 작업 DB는 지우지 않습니다. HTTPS IP 주소는 PC localhost·HTTP 주소와 다른 브라우저 저장소이므로 모델·대화는 별도로 저장됩니다.
