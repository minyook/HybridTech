# Wi-Fi AP 수신 코드 추가 시험 — 2026-11-04

**결과: 통과.** 전체 JVM 검사 99개 통과, 2개 선택 실행 평가 제외, 실패/예외 0개. 이 중 새 통신 시나리오 7개가 모두 통과했다. 검사한 운영 코드 기준은 `538858b`다. 이번에는 운영 코드 수정 없이 회귀 테스트와 측정 기록을 추가했다.

이 시험은 **PC에서 앱의 실제 `WifiMeterServer`와 배포한 Node 시험 송신기를 직접 연결한 loopback TCP 시험**이다. 연결한 Android 기기와 실행 가능한 AVD가 없어 실제 휴대폰 AP 생성·무선·Android 화면 검사는 수행하지 않았다.

## ACK 왕복 시간

16개 동시 송신 시험의 PC 내부 왕복 측정값이다.

| 중앙값 | P95 | 최대 |
|---:|---:|---:|
| 0.675ms | 1.219ms | 3.696ms |

수신기 파싱·등록·ACK·PC 운영체제 스케줄링을 포함한다. **감지기 물리 응답·Wi-Fi 전파·간섭·차폐·휴대폰 UI 반영·편도 지연을 측정한 값이 아니다.** 100ms는 목표 송신 주기이며 PC 타이머가 정확한 간격을 보장하지 않으므로 이론적 목표 건수와 ACK 건수의 차이를 패킷 손실로 계산하지 않았다. 수신기의 장비별 순번 누락 검사는 0건을 확인했다.

서버 재시작 시험은 동일한 합성 토큰을 사용해 TCP 재접속을 검증했다. 실제 AP를 껐다 켜면 연결 정보가 바뀔 수 있으므로 감지기 설정 재등록 경로는 별도 실기기 시험 대상이다. 이 시험의 16개는 소프트웨어 TCP 상한이며 휴대폰이 실제 무선 감지기 16대를 수용한다는 뜻이 아니다.

## 재실행

저장소 루트, Node.js와 프로젝트 JDK/Gradle 설정이 준비된 PowerShell에서 실행한다. 인터넷과 실제 AP 암호는 사용하지 않는다.

```powershell
$env:FIELDGUARD_WIFI_AP_STRESS='1'
$env:FIELDGUARD_EVALUATE_150='0'
.\gradlew.bat :app:testDebugUnitTest --rerun-tasks --offline --console=plain
Remove-Item Env:FIELDGUARD_WIFI_AP_STRESS
```

환경변수가 없으면 새 장시간 통신 검사는 건너뛴다. 기본 프레임·순번·신선도·TCP 회귀 검사는 기존 방식으로 실행한다. 시험 코드: `app/src/test/java/com/minyook/sllm2/gas/WifiMeterStressTest.kt`. 원시 시나리오 결과는 `tmp/wifi-ap-stress-20261104/`, 전체 HTML은 `app/build/reports/tests/testDebugUnitTest/index.html`이다.
