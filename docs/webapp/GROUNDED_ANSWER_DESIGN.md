# 문서 본문 우선 응답·AI 중단과 복구 설계

갱신: 2026-10-21. 적용 범위는 **iPhone/iPad 웹/PWA의 Qwen3/WebLLM 경로**입니다. Android 설치형의 LiteRT-LM 내부 추론 루프나 BLE 경보를 수정한 문서가 아닙니다. PC·Android 브라우저의 Gemma 생성 경로는 유지하되 Worker 중단·복구 프로토콜은 공통으로 적용합니다.

## 하나의 답변 계획

`web/src/rag/answer-plan.ts`의 `createAnswerPlan(question, sources)`가 다음을 한 번 구성합니다.

- 설명 범위는 문서 설명으로 고정합니다. 현장 측정값·승인 상태를 추측하지 않습니다.
- 문서 ID·실제 PDF 페이지·청크/항목 ID와 조건·행동이 포함된 원문 단위를 보존합니다.
- 수치의 원문 표현과 값·단위·비교 연산자를 함께 보존합니다. 범위의 비교 연산자가 명시되지 않으면 임의로 채우지 않습니다.
- 도식의 X·①~③처럼 그림 확인이 필요한 항목은 `requiresFigure`로 표시합니다. 도식·표·의학적 내용은 별도 도메인 검수가 필요합니다.
- 문서 본문과 모델 입력은 같은 계획을 사용합니다. 계획/패키지의 출처 연결 검사는 사람의 전문 검수를 뜻하지 않습니다.

`App.tsx`는 생성 준비 전에 본문을 표시합니다. 검색에서 질문에 관련된 페이지와 항목을 선택합니다. 세부 질문은 직접 답하는 항목을 먼저 표시하고 관련 조건·절을 이어 붙입니다. CPR 같은 순서 표는 전체 절차와 원문 순서를 유지합니다. 본문을 먼저 표시한 뒤 상단을 AI 문장으로 교체하지 않습니다. 선택한 근거는 출처 카드로 연결하고 기존 대화는 재작성하지 않습니다.

일반 절차·수치 질문은 이 본문으로 답변하며 **AI 생성 0회·0토큰**입니다. 왜/이유/차이/비교/뜻/의미/쉽게 풀기처럼 추가 설명을 요청할 때만 한 번의 보충 생성을 시도합니다. 단순 표현 분류의 한계가 있으며 일반 의도 이해 모델을 새로 설치하지 않습니다. 본문과 같은 요약을 의무적으로 생성하지 않습니다.

## 질문 초점과 문단 선택

2026-10-21 후속 수정은 웹/PWA의 공통 검색, Apple 본문 조립, Gemma 웹 입력과 원문 폴백에 적용합니다. Android 설치형 `KnowledgeRepository.kt`는 이 수정의 대상이 아닙니다.

기존 방식은 페이지 안에 질문 단어가 있으면 전체 페이지를 답변에 붙였습니다. 어두운 곳의 전등 질문도 27쪽을 찾고 ‘방폭’이라는 단어가 포함되어 기존 평가를 통과했지만, 실제 앞부분은 측정기 준비와 측정방법이었습니다. 페이지가 맞는지와 질문에 답하는지는 다른 검사입니다.

- `web/src/rag/text.ts`: 검색에만 동의어/조사 정규화를 적용합니다. 조명·랜턴은 전등, 표지판은 표지 등으로 연결하되 출력 원문은 변경하지 않습니다. 명사와 무관한 요청 말투를 줄이고 전압·방수등급·가격 같은 미지원 명사를 임의로 버리지 않습니다.
- `web/src/rag/search.ts`: 전체 페이지 빈도로 단어의 구체성을 정하고, 기존 주제 사전에 없는 단어도 실제 본문으로 검색합니다. 활용형은 원문에서 확인되는 어간과 연결합니다. 단어 사이 공백은 보존하여 ‘정전 등’/‘등 급기’를 ‘전등’/‘등급’으로 합치지 않습니다. 쪽 점수에 항목 내부 동시 출현과 길이를 함께 반영하고 목차·양식·사례의 영향을 줄입니다. 이것은 로컬 어휘 검색이며 범용 의미 임베딩 검색을 새로 넣은 것은 아닙니다.
- `web/src/rag/evidence.ts`: 한 bullet 안의 문장에 같은 `group`을 부여합니다. `Source.evidenceOrders`는 직접 답하는 항목과 같은 절/관련 조건을 지정하며, ‘다만/이 경우’가 의존하는 앞 항목을 함께 유지합니다. 실제 `chunk.body`는 수정하지 않습니다. 한 쪽에 대한 여러 질문은 선택 항목을 중복 없이 합칩니다. 보조 출처와 순서 표는 원문 순서를 유지합니다.
- `web/src/rag/answer-plan.ts`, `web/src/ai/runtime.ts`: 화면과 Apple AI 계획, Gemma 웹 프롬프트, 원문 폴백이 선택 항목을 공유합니다. 기기에 저장된 모델·설정·기존 답변은 재작성하지 않습니다. 질의 이력으로 검색을 학습하거나 질문 문장을 정답 페이지에 매핑하는 표를 사용하지 않습니다.

‘전등 종류’에는 가연성가스 가능성과 방폭구조 전등 문단을 먼저 표시합니다. ‘랜턴 방수 IP 등급’에는 문서에 없는 사양 대신 다른 절차를 붙이지 않습니다. ‘감시인은 안과 밖 중 어디에 배치’의 안/밖은 독립 질문으로 분리하지 않습니다. [PC에서 실제 App의 Apple 본문 경로 확인](../../web/docs/screenshots/focused-lamp-answer-pc.jpg).

새 개발 회귀는 `web/tests/focused-retrieval.json`의 33문항입니다. 첫 400 source 문자 내 직답, 조건, 제외할 절차, 문서 밖 질문을 검사합니다. 원문에 없는 새 명사를 사용한 합성 문서·조건/행동 묶음·복합 질문·원본/직렬화 보존도 자동 검사합니다. 기존 구현 `7ed8418`을 같은 원문/평가표/채점 코드로 다시 불러온 결과 **직답/본문 9/33 → 33/33**, **정답 페이지 23/33 → 33/33**입니다. 두 결과의 corpus/rubric SHA-256이 같습니다. `npm.cmd run evaluate:focused`로 재실행하고 `-- --before`로 이전 구현을 재구성합니다.

이 33문항은 개발 중 사용한 회귀 집합이며 독립 holdout/사람의 의미 검수가 아닙니다. 완전한 한국어 형태소 분석이나 모든 동의어를 지원하지 않으므로 새 표현에서의 검색 누락·잘못된 근거 가능성은 남습니다. 원본 PDF와의 비교 및 지속적인 실패 사례 검수가 필요합니다. 추가 임베딩 모델/GPU 부하는 도입하지 않았습니다.

## 선택적 로컬 AI 보충

`web/src/ai/light-engine.ts`는 Qwen3 0.6B와 기존 저장 파일을 사용합니다. 문맥 2,048·prefill 64를 유지하고 보충 출력은 기본 256/선택 128토큰입니다. 설정 키는 `ai-settings-light-v3`이며 이전 v1/v2/Gemma 설정을 삭제하지 않습니다.

시스템 지침·출력 전체·템플릿 여유 96토큰을 제외한 실제 토크나이저 예산에 **필수 근거 전체**가 들어가지 않으면 생성을 생략합니다. 조건을 잘라내거나 여러 번 생성하지 않습니다. 기존 전체 절차 순차 재작성은 새 Apple 경로에서 사용하지 않습니다.

모델은 근거 ID와 짧은 보충 문장을 JSON으로 반환합니다. 출처 누락/잘못된 ID, 본문 복사, 새로운 수치, 일부 조건 누락, 작업 허용 표현, 미완성 JSON·길이 종료 등은 표시하지 않습니다. 검사를 통과한 보충만 본문 맨 아래에 한 번 붙입니다. 미검증 토큰은 화면에 스트리밍하지 않습니다. 이 필터는 **완전한 의미 검증기가 아니며 환각 0을 보장하지 않습니다.**

AI 준비/생성/검증에 실패해도 먼저 표시한 문서 본문은 유지합니다. 문서만 표시하는 보호 동작은 AI 정상 지원과 구분합니다. SDK 사용량이 있으면 실제 값을 저장하며 보충이 거부되어도 실제 생성 토큰을 0으로 바꾸지 않습니다. 생성하지 않은 경우에만 0으로 표시합니다.

## 중단·정리·재적재 잠금

`web/src/ai/protocol.ts`는 `stop` 요청과 `stopped { cleanupComplete }` 응답을 정의합니다. 중단 요청은 Worker의 애플리케이션 busy 검사보다 먼저 처리합니다. Worker 이벤트 루프/네이티브 호출이 막혔을 때도 즉시 실행된다고 보장하지 않습니다.

1. 사용자 중단 후에는 진행 중인 답변의 화면 반영을 막습니다.
2. Apple은 `interruptGenerate()`로 정상 중단을 요청합니다. LiteRT 웹은 스트림 처리 지점에서 중단하고 대화를 정리합니다. 어느 쪽도 단일 토큰/수십 ms 내 중단을 보장하지 않습니다.
3. 실행 루프 종료 후 엔진 unload/delete와 GPU 장치 정리를 기다립니다. 중단 요청 수신과 정리 완료는 다른 사건입니다.
4. 메인 페이지가 2초 watchdog을 관리합니다. Worker가 응답하지 않거나 정리 실패를 알리면 강제 종료하고 미확인 기록을 남깁니다. 백그라운드/OS 중단 상황의 실시간 기한은 보장하지 않습니다.
5. 정상 완료·정상 중단 후 정리 확인은 다음 준비를 허용합니다. 정상적으로 정리한 Worker에도 `terminate()`를 호출하므로 이 함수 호출 자체를 실패 판정에 사용하지 않습니다.
6. 강제 종료·정리 미확인은 자동 재적재를 잠급니다. 새로고침으로 잠금을 해제하지 않습니다. 명시적인 설정 복구에서 엔진 잠금을 확보한 뒤 재시도합니다.

현재 웹은 실제 BLE 가스 경보를 수신하지 않습니다. Android의 실시간 경보와 AI 중단 연동·프로세스 격리·하드웨어 검증은 이 변경으로 구현/인증된 기능이 아닙니다.

## 지속 복구 기록

`web/src/ai/recovery.ts`의 localStorage `fieldguard-ai-operation`은 기존 version 1을 호환하며 작업 ID·단계·문맥·시각에 런타임/모델 버전과 불확실 상태·이유를 추가합니다. 적재 직전 기록을 쓰고 다시 읽어 확인합니다. Apple에서 저장할 수 없으면 GPU 적재 요청을 보내지 않습니다.

완료 미확인은 Jetsam 진단이 아닙니다. 일반 닫기·새로고침·다른 화면의 진행 중 작업일 수도 있습니다. 기록을 이유 없이 만료시키거나 기기를 영구 금지하지 않습니다. Web Locks는 지원되는 같은 저장 영역에서 중복 엔진을 막고, 복구 시 다른 화면이 잠금을 보유하면 그 화면의 기록을 지우지 않습니다. 브라우저별 저장 영역 분리는 제어할 수 없습니다.

## 관리자 PC 패키지 초안

저장소의 `web/`에서 `npm.cmd run package:knowledge`를 실행하면 `web/.local/knowledge-package-v1.json`을 생성합니다. 87개 원본 페이지의 해시, 출처 연결, 원문 항목, 수치/연산자, 조건·도식 표시를 담습니다. 상태는 `draft-not-approved-for-publication`이며 사람의 검수 후 배포하는 관리자 제품/서명·배포 기능은 아직 아닙니다. 현재 실행 데이터는 기존 `app/src/main/assets/knowledge/seed_chunks_v1.json`에서 준비합니다.

## 평가와 출시 조건

`web/tests/evaluation-150.json`은 제공된 2022 문서에서 작성한 120개 단일/표현변형·20개 복합·10개 문서 밖 질문입니다. 정답 페이지 대안, 필수 구절, 금지 표현, 예외 구절을 기록하고 원본 페이지에 해당 구절이 있는지 별도로 검사합니다. 정답은 검색 결과에서 자동 생성하지 않았습니다. 평가표는 엔지니어링 출처 확인 상태이며 도메인 담당자의 독립 검수는 남아 있습니다.

- 변경 전: `web/docs/evaluation-150-baseline.json` — 검색/본문 필수 구절 **132/150**.
- 변경 후: `web/docs/evaluation-150-after.json` — 검색/본문 필수 구절 **150/150**.
- 실행: `cd web` → `npm.cmd run evaluate:150`.
- 두 파일의 원문·평가표 SHA-256이 같아야 비교할 수 있습니다. 변경 전 결과는 검색 수정 전에 동결했습니다.
- **개발 회귀 집합으로 검색 보완에 사용한 결과**이며 보지 않은 질문의 일반화 점수나 생성 정확도 100%를 뜻하지 않습니다.
- 시간은 PC 검색/본문 조립 시간입니다. 150문항의 실제 GPU 생성 TTFT·전체 생성 시간은 측정하지 않았고 `generatedAnswer: not-run`으로 명시합니다.

출시 조건은 답변 품질과 실제 iPhone 안정성을 별도로 평가합니다. 기기 적재·연속 질문·중단·재실행·백그라운드 복귀·오프라인 및 메모리 압박 시험이 필요합니다. 모델 가중치 적재 비용은 보충 생성 축소로 없어지지 않습니다. 실제 iPhone 결과를 PC 테스트나 보호 모드 성공으로 대체하지 않습니다.
