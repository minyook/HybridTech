## 현재 유지할 동작

- Android 설치형 앱과 `web/` PWA는 독립 실행하되 현재 웹 디자인을 기준으로 공통 화면을 맞춘다. Android의 로컬 질문·BLE·음성·위젯은 유지하고, 새 작업 전 점검/감독관은 `NativeWorkPage.kt`에서 같은 서버의 웹 화면을 사용한다. 기존 앱 데이터와 서명을 보존하고 서명이 다르면 별도 `-PdesignPreview=true` 패키지로 검증한다.
- 정적 시안 `docs/webapp-ui/`와 실제 React 앱을 혼동하지 않는다. 개발 명령은 `cd web` 후 `npm run dev`, 포트는 5174다.
- AI는 고정된 Gemma 웹 파일을 검증해 저장하고 다운로드 완료·앱 재접속 후 자동으로 준비한다. 별도의 실행·메모리 해제 버튼을 다시 추가하지 않는다.
- 모델 검사·초기화·생성은 백그라운드 AI worker에서 한다. 준비 중 질문은 완료를 기다리고 실패 시 확인된 원문을 표시한다.
- 답변/문맥 토큰 설정은 실제 SDK에 적용하고 기기 저장한다. 사용량은 SDK 측정만 표시한다.
- 생성 중 사용자 스크롤을 존중하고 토큰마다 smooth 자동 이동을 호출하지 않는다. 최신 위치 버튼으로 다시 따라갈 수 있어야 한다.
- 문서명·판본·실제 PDF 쪽수·원문 연결을 보존한다. 원문 부족·모델 실패를 정상 AI 답변으로 위장하지 않는다.
- 기본 권한은 작업자이며 감독관 전환은 오늘의 숫자 6자리 입력 화면으로 이동한다. 인증 없이 감독관 목록·승인 화면이나 API에 접근할 수 없다. 서버 CLI `today / rotate / revoke`로 코드를 관리하며 여러 감독관이 당일 코드를 공유한다. 한국 시간 자정에 코드와 권한을 만료한다. `.local/` DB·비밀키·실제 코드·쿠키를 Git이나 프런트엔드에 넣지 않는다. 공유 코드의 기기 인증과 개인 로그인·현장 배정은 구분한다.
- 새 점검은 `/api/`와 SQLite에서 관리하고 IndexedDB의 이전 로컬 작업은 읽기 전용으로 보존한다. 인증·서버 API는 서비스 워커에 캐시하지 않는다. 문서·PDF·기기 내 AI의 오프라인 기능은 유지한다.
- 웹 가스값·위험 예측·탈출 경로를 임의 생성하지 않는다. 실제 BLE·경보는 검증된 Android/장비 경로에서 연결한다.

## 변경 후 확인

```powershell
cd web
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

변경에 맞는 회귀 검사와 실제 브라우저 검증을 수행한다. 긴 답변은 자동 따라가기·위/아래 수동 탐색·최신 답변 복귀·완료 후 위치 유지·모바일을 확인한다. PWA·오프라인은 개발 서버가 아닌 프로덕션 빌드로 검사한다.

README·현행 설계서·검증 기록의 상태, 테스트 수, 실행 주소와 미구현 항목을 같이 갱신한다. 실제 iPhone이나 센서 시험을 하지 않았으면 검증 완료로 쓰지 않는다. 임시 영상·개인 기록·다운로드한 모델·자격 증명·생성 빌드 파일은 커밋하지 않는다. 푸시 전 변경 파일과 원격 브랜치 상태를 확인하고 강제 푸시는 하지 않는다.
