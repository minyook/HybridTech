# 완전 오프라인 밀폐공간 안전 RAG 설계

## 이번 구현의 범위

이 앱은 네트워크를 사용하지 않아도 제공된 안전 문서를 검색하고, Gemma 4 E2B 모델 설치가 끝난 뒤에는 기기 내부에서만 답변을 생성한다. APK에는 대형 모델을 넣지 않는다. 첫 사용자가 직접 내려받은 모델은 앱 전용 `noBackupFilesDir/models`에 보관하며, DB와 모델 상태는 프로세스 종료와 재부팅 뒤에도 유지된다.

```text
PDF 원문 페이지(87개) --첫 실행 1회--> ObjectBox + HNSW 벡터
                                         |                 ^
사용자 질문 --> 384차원 로컬 검색 벡터 ----+                 |
                                         v                 |
                             상위 근거 페이지 4개 --> 프롬프트 --> LiteRT-LM / Gemma 4 E2B
```

## 데이터베이스와 검색

`ObjectBox 5.4.2`를 선택했다. 같은 로컬 DB에 원문, 페이지 번호, 문서 이름, 검색 벡터를 함께 보관하고 HNSW 코사인 검색을 수행한다. 앱을 다시 열 때 전체 벡터를 RAM으로 다시 적재할 필요가 없는 구조라, 문서가 늘어나는 상용 환경에 적합하다.

초기 번들에는 원문을 즉시 검색할 수 있도록 384차원 해시 기반 임베딩을 넣었다. 이는 설치 크기와 초기 대기 시간을 늘리지 않는 안전한 부트스트랩 검색 계층이다. 제품 출시 전에는 같은 384차원 스키마를 유지한 채 `EmbeddingGemma 300M` 같은 온디바이스 문장 임베딩 모델로 교체해야 한다. 생성 모델(Gemma 4 E2B)과 임베딩 모델은 역할이 다르므로, 한국어 의미 검색 품질을 상용 수준으로 올리려면 이 별도 모델이 필요하다.

각 청크는 PDF 한 페이지를 절대 넘지 않는다. 답변에 `문서명 n쪽`을 붙여 작업자가 원문을 다시 확인할 수 있고, 가이드 개정 시 `seed_chunks_v2.json`을 추가해 버전을 올리면 DB를 원자적으로 교체할 수 있다. 사용자가 추후 추가하는 개인 문서는 기본 문서와 별도 `documentId`/컬렉션으로 분리하여, 업데이트 시 삭제되지 않게 해야 한다.

## 제공 문서 분석과 반영 내용

`seed_chunks_v1.json`에는 점검표 3쪽과 2022 가이드 84쪽의 텍스트 레이어를 모두 추출해 총 87개 페이지 단위 청크로 보관했다. 특히 가이드의 다음 규칙을 첫 화면의 닫을 수 없는 Critical Callout과 검색 근거에 반영했다.

| 주제 | 핵심 내용 | 근거 페이지 |
| --- | --- | --- |
| 밀폐공간 식별 | 현재 유해가스가 없더라도 누출·유입 가능성을 포함해 목록화하고 관리한다. | 가이드 18쪽 |
| 작업허가 | 안전조치가 적정하다고 확인된 경우에만 작업을 허가하는 내부 절차가 필요하다. | 가이드 20쪽 |
| 적정 공기 | 산소 18.0% 이상 23.5% 미만, CO2 1.5% 미만, CO 30ppm 미만, H2S 10ppm 미만이다. 작업 전·재개 전·작업 중 수시로 측정한다. | 가이드 24쪽, 점검표 2쪽 |
| 환기 | 최초 진입 전 신선한 공기로 최소 15분 및 공간 체적 10배 이상 환기 후 측정하고, 발생·유입 위험이 있으면 작업 중 계속 환기한다. | 가이드 28쪽, 점검표 3쪽 |

안전 답변은 모델이 준비되지 않아도 먼저 문서 근거를 보여준다. 모델 답변은 위 근거만 사용하도록 프롬프트를 고정하고, 근거가 없으면 추측하지 않게 한다. 이 앱은 법정 판단이나 긴급 구조 지휘를 대체하지 않는다.

## Gemma 4 E2B 모델 수명주기

1. 사용자가 설치 버튼을 누르면 WorkManager가 유일한 다운로드 작업을 만든다.
2. `.part` 파일과 HTTP Range 요청으로 중단 지점부터 이어받는다.
3. 서버의 `Content-Length`와 최소 파일 크기를 확인한 뒤에만 원자적으로 `.litertlm` 최종 파일로 이름을 바꾸고 `READY` 상태를 저장한다.
4. 앱 재시작 시 최종 파일 크기를 다시 확인해 준비 상태를 복원한다.
5. 답변 시 LiteRT-LM 엔진을 백그라운드에서 초기화한다. 권장 기기에서는 GPU를 먼저 시도하고 실패하면 CPU로 즉시 폴백한다. 저사양 기기는 처음부터 CPU를 사용한다.

범용 Gemma 4 E2B LiteRT-LM 파일은 약 2.59GB이므로 설치 전 4GB 이상 여유 공간을 안내한다. 8GB RAM 이상 ARM64 기기를 권장하며, 그보다 낮은 기기는 다운로드를 막는 대신 CPU 우선 모드와 짧은 근거 컨텍스트를 사용하도록 제품 정책을 정할 수 있다. ObjectBox와 현재 LiteRT-LM 구성은 64비트 ABI(`arm64-v8a`, 에뮬레이터 `x86_64`)를 대상으로 한다. 32비트·저메모리 기기에까지 반드시 서비스를 제공해야 한다면, 별도의 초소형 모델과 텍스트 검색 전용 모드를 제품 SKU로 분리하는 것이 안전하다.

## 출시 전 필수 보강

- 현재 모델 URL은 공개 LiteRT Community 원본을 가리킨다. 운영에서는 버전, 바이트 수, SHA-256, 서명, 모델 카드·라이선스를 담은 자체 HTTPS 매니페스트를 배포하고 서명 검증 후 설치한다.
- `latest.release` SDK는 개발 편의용이다. QA를 통과한 LiteRT-LM 버전을 고정하고, 해당 버전과 모델 파일 조합을 실제 기기 매트릭스에서 회귀 테스트한다.
- Samsung/Qualcomm/MediaTek/Tensor별 6GB·8GB·12GB RAM 기기에서 첫 토큰 시간, 초당 토큰, 최대 RSS, GPU 실패 CPU 폴백, 다운로드 중 앱 강제 종료를 측정한다.
- 사용자가 추가한 PDF는 암호화된 앱 저장소에 유지하고, "이 문서에서 삭제"와 전체 모델·지식 초기화 기능을 별도 제공한다. 기본 안전 가이드 업데이트와 개인 문서 삭제를 섞지 않는다.
- 대형 다운로드는 Android 16 이상의 사용자 시작 데이터 전송 정책과 포그라운드 알림 권한을 실기기에서 검증한다.

## 디자인 원칙

Seed Design의 짧고 직접적인 탭 라벨, 상태 배지, Card/Callout의 정보 위계를 참고했다. 다만 위험 경고는 일반 안내와 달리 닫거나 약하게 만들지 않는다. 따뜻한 주황색은 행동 버튼에만 쓰고, 적정 공기 미확인 상태는 높은 대비의 빨간 Callout으로 고정해 안전 행동이 UI에서 묻히지 않게 했다.
