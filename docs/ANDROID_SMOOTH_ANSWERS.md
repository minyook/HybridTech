# Android 생성 답변의 부드러운 표시

갱신: 2026-11-10. Android Compose 채팅과 같은 목록을 사용하는 음성 대화 화면에 적용한다. 모델 파일과 저장된 대화는 다시 받거나 변환하지 않는다.

## 바꾼 동작

기존에는 검증을 통과한 완성 문장·문단을 한 번에 추가했다. 이제 그 본문을 작은 글자 묶음으로 나누어 화면 프레임에 맞춰 표시한다. 모델의 미검증 토큰을 먼저 공개하는 방식은 아니다. 일반 지식 안내와 이미 표시한 문서 본문은 고정하고 새로 생성한 부분만 이어 쓴다.

문서 검색으로 구성한 본문과 과거 대화는 즉시 표시한다. 생성 결과가 수정·거절되면 이전 텍스트를 천천히 지우지 않고 검증된 결과로 즉시 바꾼다. 표와 코드 블록은 완성된 구조로 표시하고, 유니코드 문자·이모지 쌍과 Markdown 기호가 중간에서 잘리는 것을 완화한다. 생성 완료 후 남은 표시 버퍼는 약 0.2초 안에 따라잡도록 설계했다. 앱 일시 정지나 바쁜 UI 스레드의 실제 프레임 지연까지 보장하는 시간은 아니다.

120 Hz 화면에서도 텍스트 레이아웃 갱신은 최대 초당 약 30회로 제한한다. 글자마다 자동 스크롤 애니메이션을 취소·재시작하지 않으며, 진행 중인 이동이 최신 끝 앵커를 따라가게 한다. 사용자가 위쪽으로 읽으면 따라가기를 멈추고 맨 아래로 돌아오면 재개한다. 전체 복사와 저장에는 최종 본문을 사용한다.

추가로 “5개 항목을 각 항목 한 문장으로”를 전체 1~3문장 요청으로 해석하던 간결성 분기를 고쳤다. 항목별 길이 제한과 전체 답변 길이 제한을 구분한다. 자동/수동 최대 출력 설정은 유지하며 모든 답변을 짧게 강제하지 않는다.

## 속도 측정의 의미

부드러운 표시가 모델의 토큰 생성 속도를 높였다는 뜻은 아니다. 아래 시간을 별도로 기록한다.

- `firstNativeTextMs`: 네이티브 엔진의 첫 텍스트 도착. 안전 검사 전이므로 화면에 표시한 첫 본문 시간이 아니다.
- `firstAcceptedBodyMs`: 기존 검사기가 처음 공개할 수 있는 본문을 반환한 시점. 실제 디스플레이 프레임은 별도 계측하지 않았다.
- `totalMs`: 엔진 준비와 해당 요청의 전체 직접 생성 시간. 시험의 사전 준비 요청은 `warmupMs`로 별도 기록한다.
- `decodeTokens` / `tokensPerSecond`: 시험에서만 활성화한 SDK 벤치마크 정보. 제품 실행 설정이나 기존 미측정 결과를 이 값으로 대체하지 않는다.

시험은 Gemma 4 E2B / S24 Ultra / GPU / 문맥 4,096에서 진행한다. 현장 질문은 항목 수와 항목별 한 문장을 명시한다. 장문의 자유 생성과 같은 분량이라고 해석하지 않는다. 출력 한도는 시험에서 1,024토큰이며, 한도 도달 여부와 원문을 함께 기록한다. 제품의 사용자 설정은 변경하지 않는다.

### S24 실측 결과

| 직접 생성 질문 | 출력 | 화면 없는 전체 생성 | 채팅·녹화 포함 첫 공개 가능 본문 | 채팅·녹화 포함 전체 생성 |
| --- | --- | --- | --- | --- |
| 밀폐공간 작업 재개 전 감독관 확인 사항, 5개 항목·항목별 한 문장 | 532자 / 277토큰 | 13.768초 | 0.896초 | 18.498초 |
| 밀폐공간 인명구조용 삼각대 준비 수량의 고려 조건, 4개 항목·항목별 한 문장 | 421자 / 220토큰 | 14.074초 | 2.788초 | 16.651초 |

두 조건의 생성 원문은 질문별로 동일했고, 지정한 5개/4개 번호 항목으로 끝났으며 출력 한도에 닿지 않았다. 별도 사전 준비 요청은 화면 없는 시험 11.762초, 녹화 전 시험 11.493초였다. **위 전체 생성 시간에 사전 준비 요청은 포함하지 않는다.** 정확한 값은 원시 JSON의 `warmupMs`를 기준으로 한다.

목표한 전체 8~9초 완료는 달성하지 못했다. 화면 없는 시험도 13.8~14.1초였으므로 표시만 바꿔서 해결됐다고 볼 수 없다. UI와 녹화가 함께 있는 시험의 추가 지연을 애니메이션 단독 비용으로 해석하지 않는다. 표시 부하·열 상태·측정 순서 등의 효과를 분리하려면 반복·순서 교차 시험이 필요하다.

생성 품질도 별도다. 첫 질문의 모델 출력에는 가스 농도 재측정을 명시한 항목이 없고, 두 번째는 구체적인 구조계획 대신 포괄적인 조건을 설명한다. 이 시험 통과는 실제 문서 근거 답변이나 작업 재개 체크리스트의 정확성 합격이 아니다. 제품에서는 기존 문서 우선 경로를 유지한다.

화면 없는 시험과 화면·녹화를 포함한 시험은 조건이 다르다. 개별 실행 시간으로 애니메이션이나 녹화만의 비용, 모든 기기의 성능, 정확도 개선을 확정하지 않는다. RAG 문서 바로 표시 경로의 속도와도 구별한다. 이 시험의 생성 본문은 일반 모델 출력이며 검수된 작업 매뉴얼이 아니다.

## 구현 경로

모두 저장소 루트 기준이다.

| 파일 | 역할 |
| --- | --- |
| `app/src/main/java/com/minyook/sllm2/ui/StreamingTextReveal.kt` | 검증된 본문의 표시 버퍼, 프레임 갱신, 복원 대화·수정·표 처리 |
| `app/src/main/java/com/minyook/sllm2/ui/FieldGuardViewModel.kt` | 일반 생성 중간 본문에만 애니메이션 표시, 완료 시 기존 메시지 상태 유지 |
| `app/src/main/java/com/minyook/sllm2/ui/WorkspaceScreens.kt` | 표시 본문과 lazy 목록 연결, 글자 갱신 중 끝 따라가기 유지 |
| `app/src/main/java/com/minyook/sllm2/data/GeneralKnowledgeAnswer.kt` | 기존 일반 지식 검증과 항목별 길이 요청 해석 |
| `app/src/test/java/com/minyook/sllm2/ui/StreamingTextRevealTest.kt` | 작은 표시 단계·완료·수정·과거 대화·이모지·표 회귀 |
| `app/src/test/java/com/minyook/sllm2/data/GeneralKnowledgeAnswerTest.kt` | 전체 문장 수와 항목별 문장 수의 구분 |
| `app/src/androidTest/java/com/minyook/sllm2/ChatScreenTest.kt` | 실제 Compose의 표시 프레임·스크롤·키보드·복사·출처 검사 |
| `app/src/androidTest/java/com/minyook/sllm2/ReferenceAnswerStreamingTest.kt` | 선택 실행하는 실제 네이티브 생성, 임시 대화 화면, 시간·원문 JSON |

`ReferenceAnswerStreamingTest`는 `runReferenceStream=true`를 명시해야 실행한다. `presentation=off`는 화면 없는 생성, 기본값 `smooth`는 제품 채팅 UI를 사용한다. 실제 모델 파일이 필요한 시험이며 사용자 채팅과 비교 보고서·설정을 덮어쓰지 않는다.

이 시험은 실제 `WorkspaceChat`을 표시하지만 `FieldGuardViewModel.submitQuestion()`을 호출하지 않는다. 문서 검색·이전 대화·사용자가 저장한 설정 대신 준비된 GPU 엔진·빈 대화·고정 설정으로 `LocalModelRuntime.generate()`를 직접 호출한다. 따라서 같은 질문을 실제 앱에서 입력했을 때의 답변이나 지연을 재현한 시험은 아니다. 제품 성능 합격은 보내기부터 검색·모델 적재·첫 본문 공개·완료까지 같은 경로로 측정해야 하며, 새 대화/기존 대화와 첫 실행/반복 실행을 구분한다. 이 추가 제품 경로 실측은 아직 완료되지 않았다.

```powershell
adb shell am instrument -w -r `
  -e class com.minyook.sllm2.ReferenceAnswerStreamingTest `
  -e runReferenceStream true -e presentation smooth `
  -e timeout_msec 240000 `
  com.minyook.sllm2.test/androidx.test.runner.AndroidJUnitRunner
```

실측 결과와 최종 검사 기록은 [검증 기록](validation/android-smooth-answers-20261110.json)에 정리한다. 원본 질문·생성 본문·도착 시각은 [원시 계측 자료](validation/smooth-answers-20261110/)에 보존한다.

최종 검증: JVM 181개 통과·선택 실행 10개 제외·실패 0개, 실제 S24 `ChatScreenTest` 13개 통과, 최종 직접 생성 4회 완료·출력 한도 미도달, 앱/계측 APK 빌드와 서명 확인 통과, Lint 오류 0개·경고 112개. APK는 S24에 데이터 삭제 없이 교체 설치했다. 키보드 검사는 fixture 높이 변화이며 전체 실제 IME 검증은 아니다. 네이티브 생성 fixture는 앱 헤더·하단 탐색을 제외한 실제 `WorkspaceChat`을 사용하므로 전체 앱 디자인 캡처와 구별한다.

처음 영상과 같은 레시피 질문을 사용한 초기 표본은 [초기 기록](validation/smooth-answers-20261110/reference-smooth.json)에 보존했다. 512토큰 한도로 잘렸으므로 완성 속도 합격으로 집계하지 않는다. “항목별 한 문장” 수정 전의 지나치게 짧은 출력도 [수정 전 기록](validation/smooth-answers-20261110/reference-field-off-before-length-fix.json)으로 분리했다. 최종 4회 지표에는 이 표본들을 섞지 않았다.
