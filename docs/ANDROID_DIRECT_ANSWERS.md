# 질문에 바로 답하는 처리

기준: 2026-11-10. Android의 주제 선택 메뉴 생성·본문 목록 삽입·선택 버튼을 제거했다.

## 현재 동작

검색 후보 점수가 비슷하다는 이유로 ‘세 가지 중 궁금한 범위를 선택해 주세요’라고 되묻지 않는다. 직접 근거를 확인하면 문서 본문으로 답하고, 검색이 완료됐지만 직접 근거를 확정하지 못한 구체적인 질문은 **사용자가 입력한 원래 문장**을 일반 설명 생성으로 전달한다. 생성 모델이 준비되지 않았다면 기존 모델 준비 안내를 사용한다.

검색 신뢰도 기준을 낮춰 첫 번째 후보를 정답으로 고르지 않는다. 인코더/인덱스 오류는 오류로 유지하고, 대화 없이 ‘그거?’처럼 대상 자체가 없는 경우에는 필요한 대상을 한 문장으로 확인한다. 복합 질문의 내부 검색은 유지하며 결과를 하나의 답변으로 합친다.

## 구현 경로

| 파일 | 책임 |
| --- | --- |
| `app/src/main/java/com/minyook/sllm2/data/HybridRetrieval.kt` | 새 주제 선택지 생성 제거. 검토를 마친 미확정 질문을 일반 생성으로 연결 |
| `app/src/main/java/com/minyook/sllm2/data/QuestionSearchCoordinator.kt` | 선택지 본문 조립·재제안 제거. 이전 기록의 선택지 재표시 요청도 주제 자체를 검색 |
| `app/src/main/java/com/minyook/sllm2/data/ConversationContext.kt` | 선택 목록을 본문에 붙이던 확장 함수 제거. 기존 대화 메타데이터 해석 호환 유지 |
| `app/src/main/java/com/minyook/sllm2/ui/WorkspaceScreens.kt` | 선택 버튼 제거. 실제 문서 출처 버튼은 유지 |

기존에 저장된 답변 본문을 다시 쓰지 않는다. 저장된 옛 선택 메타데이터가 있어도 버튼을 표시하지 않으며, 새 질문에는 선택 목록이 생성되지 않는다. `SearchSuggestion` 타입/저장 필드는 이전 JSON 기록 호환을 위해 유지한다.

## 검증

- 후보 점수가 같은 경우에도 원래 질문과 ‘핵심 5개·항목별 한 문장’ 요청이 그대로 일반 생성에 전달되는지 검사한다.
- 실제 번들 원문/인덱스와 고정 ONNX 검색 모델로 사용자가 입력한 감독관 질문·가스 측정 질문을 재현한다. 이 시험은 PC Kotlin 검색 분기 검사이며 Gemma 생성/UI 시간은 포함하지 않는다.
- 검색 실패·대상 없는 질문·승인 상태·문서 직접 응답·기존 기록 호환 회귀를 유지한다.
- Compose 검사에는 pending/완료 상태 모두에서 예전 선택 메타데이터가 버튼을 다시 만들지 않는지 포함한다.
