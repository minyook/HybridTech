# Android 모델 선택과 성능 비교

갱신일 2026-11-10.

**실기기 결과:** S24 Ultra에서 36회 장문 생성과 13회 별도 진단을 완료했다. E2B의 텍스트 생성은 12/12개였지만 수치·비교 오류가 있었고, 270M·1B도 현재 설정에서 현장 장문 대체 모델로 채택할 근거가 부족했다. [실측 지표·원문·검토 의견](ANDROID_MODEL_BENCHMARK_20261110.md). 아래 2026-11-09 검증 항목은 당시의 APK·코드 검사 기록이다.

## 사용 순서

1. 설정의 기기 내 Gemma에서 사용할 모델을 선택한다.
2. Gemma 3 모델은 배포 페이지에서 약관에 동의하고 같은 계정의 Hugging Face 읽기 토큰을 발급한다. 화면의 링크로 이동할 수 있다. 토큰을 입력하고 다운로드 버튼을 누른다. 저장한 토큰은 다음 다운로드에서 재사용한다.
3. 모델마다 다운로드를 완료한다. 이전 모델 파일은 기기에 남고 선택한 모델이 다음 질문에 사용된다. 기존 Gemma 4 E2B 파일은 다시 다운로드할 필요가 없다.
4. 평소 채팅과 음성 질문에서 모델별 응답을 확인한다.
5. 설정에서 CPU 또는 GPU 실행 방식을 저장하고 **현장 복합 질문 12개 보기**로 시험 질문을 확인한 다음 **다운로드한 모델 상세 비교 시작**을 누른다. 같은 기기에서 CPU 비교를 마친 뒤 GPU로 새 비교를 시작하면 실행 방식도 비교할 수 있다. 새 비교 전에 기존 보고서를 내보낸다.
6. 진행 중인 답변을 확인하고, 완료 후 질문별 생성문과 문서 근거·품질 확인 항목을 열어 정확함 또는 수정 필요를 선택한다. **비교 결과 JSON 파일 공유**로 전체 측정과 직접 평가를 저장한다. 작은 보고서는 JSON 복사도 가능하며 큰 보고서는 파일 공유를 사용한다.

## 배포 파일과 실행 조건

| 모델 | 배포 파일 | 다운로드 크기 | 앱의 문맥 상한 |
| --- | --- | --- | --- |
| Gemma 4 E2B | gemma-4-E2B-it.litertlm | 약 2.59 GB | 기기별 한도, 최대 32,768 |
| Gemma 3 270M | gemma3-270m-it-q8.litertlm | 304,005,120 바이트 | 4,096 |
| Gemma 3 1B | gemma3-1b-it-int4.litertlm | 584,417,280 바이트 | 4,096 |

270M은 8비트, 1B는 4비트 CPU/GPU용 LiteRT-LM 배포 파일을 선택했다. 지원 칩셋에는 NPU 전용 파일을 추가 다운로드할 수 있으며 실제 실행 파일과 문맥을 결과에 기록한다. [NPU 지원 범위와 전환 정책](ANDROID_NPU.md). 문맥 상한은 앱에서 사용하는 배포 파일의 실행 조건이며 원본 모델의 이론적 최대 문맥과 구별한다. 다른 양자화와 모델 크기가 함께 달라지므로 결과는 선택한 실제 배포 파일의 비교다.

Gemma 3 파일은 2026-11-09 확인한 배포 리비전에 고정한다. 270M은 `9d2093270fb5aa49a986b49b5779d763dde7b630`, 1B는 `aa49427ccd3bcacb1820d2bc3bb969eaffe632bf`이다. 새 파일은 정확한 크기를 검증한다. 기존 E2B의 파일명과 최소 크기 판정은 설치 데이터 호환을 위해 이어서 사용한다.

배포자는 Gemma 사용 조건을 적용한다. 앱 사용자가 모델 페이지에서 약관에 동의해야 접근 가능한 배포처는 HTTP 401/403을 반환할 수 있다. 앱은 해당 응답에서 자동 재시도를 끝내고 토큰과 약관 동의를 안내한다. 토큰은 Android Keystore의 키로 AES-GCM 암호화해 저장하고 백업에서 제외한다. 토큰을 WorkManager 인자나 성능 결과 JSON에 넣지 않으며 인증 헤더는 huggingface.co에만 전송한다.

공식 배포 목록에서 파일명과 크기, 접근 조건을 확인했다. [Gemma 3 270M](https://huggingface.co/litert-community/gemma-3-270m-it/tree/main) · [Gemma 3 1B](https://huggingface.co/litert-community/Gemma3-1B-IT/tree/main) · [Gemma 4 E2B](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm).

## 비교가 측정하는 것

제품의 RAG는 문서에 직접 답이 있으면 근거 본문을 조립해 즉시 보여준다. 설정의 비교 기능은 생성 모델 성능을 보기 위해 문서 질문도 각 모델이 직접 답변하게 한다. 문서 검색과 근거 구성은 공통으로 한 번 실행하고 각 모델에 같은 근거를 전달한다.

현재 비교 묶음은 `field-detailed-v2`다. 공통 조건은 **문맥 4,096 토큰 / 최대 출력 2,048 토큰 / 자동 답변 길이 조절 끔**이다. 이전 `quick-v1`의 5문항·최대 256토큰 비교를 현장 복합 질문 12문항으로 바꿨다. 2,048은 현재 세 배포 파일의 공통 문맥과 앱의 출력 정책에서 허용하는 최대 비교 출력이다. 사용자의 평소 채팅 설정을 덮지 않는다. 질문·공통 지시·선택한 원문 근거도 입력 문맥을 사용하므로 한도를 늘렸다고 모든 답변의 완성을 보장하지 않는다.

각 질문에 대해 세부 근거 검색을 세 번 수행하고 페이지가 같아도 서로 다른 조건과 절차를 합친다. 각 모델에 동일한 질문·지시·근거를 전달한다. 검색은 공통으로 미리 수행하며 생성 계측에서 제외한다. 근거를 준비하지 못한 세부 검색은 보고서에 남겨 검색 누락과 생성 오류를 구분할 수 있게 한다. 짧은 답변 지시는 제거하고 질문 범위의 절차·조건·예외, 비교표와 담당자별 확인 사항·체크리스트를 충분히 설명하도록 요청한다. 미확인 수치·장비 사양·수량·작업 승인은 생성하지 않도록 지시한다. 이는 프롬프트이며 모델 출력의 정확도를 보장하는 검증기는 아니다.

| 번호 | 현장 복합 질문의 주제 | 비교할 설명 범위 |
| --- | --- | --- |
| 1 | 여러 가스 측정값과 작업 투입 전 점검 | 경계값·단위, 추가 점검, 환기·재측정, 승인 미확인 조건 |

| 3 | 환기 중단과 작업 재개 | 중단 직후, 환기 복구, 재측정, 감시인·감독자 점검 |
| 4 | 산소 부족과 보호구 선택 | 보호구별 사용 조건·한계, 미확인 가스, 연락·구조 |
| 5 | 여러 출입구의 구조 장비 배치 | 준비 의무와 수량 근거, 구조 경로, 장비 호환성 |

모두 가상 현장·교육 상황이다. 전체 질문 문장과 세부 근거 검색어·품질 확인 항목은 앱에서 열람하고 JSON의 `caseSpecifications`로 내보낸다. 소스는 `FieldComparisonSuite.kt`다. 모델을 세 개 설치했다면 총 36개 답변을 생성한다. 긴 생성으로 전체 비교가 수십 분 이상 걸릴 수 있다. 해당 모델의 첫 질문에는 모델 초기화 시간이 포함되며 이후 질문은 준비된 엔진을 재사용한다. 중지 버튼은 진행 중인 답변이 끝난 뒤 다음 질문부터 실행을 멈춘다.

현재 NPU 전용 파일의 앱 문맥 한도는 1,280이므로 이 상세 비교의 2,048 출력 요청은 NPU에서 실행할 수 없다. 자동/NPU 우선을 선택했더라도 범용 GPU/CPU로 전환하고 이유를 기록한다. 이 비교의 결과를 NPU 장문 성능으로 해석하지 않는다. [NPU 실행 범위](ANDROID_NPU.md).

결과는 실제 사용한 CPU/GPU, 첫 표시 가능한 완결 문장, 전체 생성 시간, 모델 준비 시간, 출력 문자 수를 기록한다. SDK가 토큰 통계를 제공할 때만 출력 토큰과 초당 토큰을 저장하며 미측정값은 null이다. 사용 가능 RAM과 발열 상태도 질문별로 기록한다. GPU를 요청했어도 초기화 실패로 CPU로 전환되면 실제 결과는 CPU로 표시한다.

모델마다 실제 출력 길이는 달라질 수 있고 최대 출력 전에 스스로 종료하거나 한도에서 답변이 중간에 끝날 수 있다. 길이를 채우기 위해 이어 쓰기를 반복하지 않는다. 전체 시간은 생성 종료까지의 시간이며 내용 완성을 보장하는 점수가 아니다. 실제 토큰 통계가 없으면 한도 도달 여부도 미측정(`null`)으로 남긴다. 평균 출력 문자 수도 함께 비교한다. 화면 렌더링과 음성 인식·낭독은 계측에 포함하지 않는다. 몇 개 질문의 단어 포함 여부로 자동 정확도를 확정하지 않고 생성문·기준 문서와 질문별 품질 확인 항목을 보고 사용자가 평가한 통과 수를 별도로 표시한다. 최종 모델 선정에는 더 넓은 평가 질문과 반복 실기기 측정이 필요하다.

앱이 종료되어 실행 완료를 확인하지 못한 보고서는 다음 실행에서 중단된 결과로 표시한다. 완료된 질문과 직접 평가는 보존한다. 처리 가능한 생성 예외는 수신한 부분 답변과 오류를 함께 저장한다. 프로세스가 강제로 종료되면 마지막으로 저장한 완료 질문까지만 복원되며 작성 중 내용의 복원은 보장하지 않는다. 이전 간단 비교 보고서는 원래 5문항·256토큰 조건으로 표시하며 새 결과로 바꾸지 않는다. 비교용 질문과 답변은 사용자 채팅 기록에 추가하지 않는다.
