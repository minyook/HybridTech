# HybridTech O₂ Field Guard Web

Kotlin Android 설치형 앱과 함께 제공하는 React + TypeScript + Vite PWA입니다. 현재 웹 디자인을 기준으로 Android 홈·문서·설정도 맞추고 작업 전 점검·감독관 화면은 앱 WebView에서 같은 서버를 사용합니다. 앱의 로컬 질문·BLE·음성·알림·위젯은 유지합니다. 전체 구성·소스와 저장 경로·Android 빌드는 [루트 README](../README.md)를 먼저 확인하세요. 웹은 iPhone, iPad, Android 브라우저와 PC에서 문서 질문, 원문 PDF, 대화 기록, 작업 전 점검을 제공합니다.

## 실행

Node.js 24.15 이상 사용. PowerShell에서는 `npm.cmd`를 사용합니다.

```powershell
cd C:\Users\limmi\AndroidStudioProjects\Sllm2\web
npm.cmd ci
npm.cmd run dev
```

개발 화면은 `http://localhost:5174/`입니다. 다른 프로젝트의 5173 서버와 구분하도록 5174를 고정했습니다. 반드시 위의 `Sllm2\web` 폴더에서 실행하세요. 포트가 이미 사용 중이면 임의의 다른 포트로 바꾸지 않고 오류를 표시합니다. 개발 화면과 프로덕션 미리보기는 같은 React 코드와 디자인을 사용합니다.

개발 모드에서는 서비스 워커를 등록하지 않습니다. PWA와 오프라인 동작은 **프로덕션 빌드**로 확인합니다.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

미리보기는 `http://localhost:4173/`입니다. `localhost`와 `127.0.0.1`은 서로 다른 저장소를 사용합니다. 이전 프로덕션 빌드가 열려 있다면 모든 같은 주소의 탭을 닫고 다시 열어 최신 버전을 확인합니다. 새 버전은 대화 중 강제로 화면을 교체하지 않습니다.

## 구현된 기능

- 데스크톱 사이드바, 모바일 하단 메뉴, 320px 이상 반응형 화면.
- 기존 JSON의 문서 2종·87개 페이지, Java 문자열 해시와 384차원 벡터, 단어 점수, 복합 질문의 주제별 근거 선택. 페이지 첫 부분의 주제 일치를 보강했습니다.
- **문서 원문 검색 / Gemma 생성 답변**을 구분합니다. 다운로드된 모델은 자동 준비하며, 준비 중 질문은 완료를 기다린 뒤 생성합니다. 모델 없음·실패·근거 부족 시 확인된 원문만 표시합니다.
- 한국어·문서 근거 지시는 시스템 메시지로 전달하고, 문서 안내에는 Top-K 1을 명시합니다. 문서에 없는 문자권 혼입·깨진 문자·심한 문장 반복·영문 이탈을 검사해 비정상 생성은 저장하지 않고 검색 원문으로 전환합니다. 이 검사는 사실 정확도 전체나 기기별 GPU 추론 오류의 해결을 보장하지 않습니다.
- 제목·강조·목록·GFM 표·코드 블록·인용 등 마크다운 답변. 표와 코드는 작은 화면에서 가로 스크롤합니다. 원문에 있던 기호는 그대로 보존합니다. 생성된 HTML을 실행하거나 원격 이미지를 자동 요청하지 않습니다.
- 답변 생성 중에도 휠·터치·키보드·스크롤바로 자유롭게 탐색할 수 있습니다. 다시 **생성 중인 마지막 줄이 보이는 위치로 내려오면** 버튼 없이 자동 따라가기를 재개합니다. 위로 읽는 동안에는 최신 줄이 보이더라도 강제로 내려가지 않으며, 입력창·상단 메뉴·모바일 키보드에 가려진 부분은 보이는 것으로 취급하지 않습니다. **최신 답변으로 이동** 버튼도 제공합니다. 생성 중·완료 후 같은 메시지 DOM을 유지해 강제 점프를 방지합니다.
- 문서 ID와 실제 PDF 쪽수의 연결, PDF.js 원본 렌더링, 확대와 앞뒤 쪽 이동, 추출 텍스트 보기.
- IndexedDB 대화·이전 로컬 점검 보존, 서버 SQLite 작업 요청·감독관 점검/승인·투입/탈출 사건 기록, 구분된 JSON v3 내보내기. 기기 기록 삭제는 서버 작업을 지우지 않습니다.
- PWA manifest, PNG 아이콘, Apple 홈 화면 설정, 버전별 앱 셸 서비스 워커.
- 문서 검색 / PDF / AI 실행 파일 준비를 구분하고 크기·SHA-256 검증 뒤 캐시합니다. 중단된 파일은 준비 완료로 표시하지 않으며, 다음 준비에서 이미 완료된 파일을 재사용합니다.
- **Gemma 4 E2B 다운로드 받기** 버튼으로 공식 웹 모델과 실행 파일을 자동 준비합니다. 주소·파일·해시 입력 없이 코드에 고정된 버전·크기·SHA-256을 사용하고 진행률·취소·OPFS 저장을 제공합니다. 기존 모델은 새 설치 검증이 성공한 뒤 교체합니다.
- 다운로드 완료·앱 재접속 시 LiteRT-LM `0.18.0` 모델을 자동 초기화합니다. 해시 검사·모델 로드·생성을 Web Worker에서 처리해 화면과 분리합니다. 진행 단계·경과 시간을 표시하고, 화면을 이동해도 준비를 계속합니다. 실행·메모리 해제 버튼은 제공하지 않으며 중단·재설정·모델 삭제 때 워커가 메모리를 정리합니다.
- 설정에서 **모델 파일 저장됨**과 **실행 준비 중 / AI 사용 가능**을 따로 표시합니다. 새로고침·재실행 시 저장된 파일을 다시 검사하고 GPU 실행 메모리에 불러오며, 준비 문구에도 재다운로드가 아님을 안내합니다. 같은 페이지에서 화면만 이동하면 기존 엔진을 재사용합니다. 영구 저장 권한은 디스크 데이터 유지에 관한 것으로 실행 메모리를 유지하지 않습니다.
- OPFS 모델은 최초 실행에서 저장 파일 전체를 검증한 뒤 그 결과를 보존합니다. 재접속 시 파일 크기·수정 시각·최대 512KiB 표본을 확인해 같으면 전체 읽기를 생략하고, 변경·검증 기록 이상·7일 경과 시 전체 SHA-256을 다시 검사합니다. 변경 시각을 확인할 수 없는 저장 방식은 전체 검사를 유지합니다. 설정에 실제 준비 시간과 파일 확인 시간, 검증 재사용 여부를 표시합니다.
- 설정에서 최대 답변 토큰(256~4,096)과 문맥 크기(4,096 / 8,192 / 16,384)를 저장합니다. 기본값은 답변 1,536 / 문맥 8,192입니다. 저장한 값은 다음 질문의 실제 SDK 옵션에 적용하며, 문맥을 바꾸면 엔진을 다시 준비합니다. SDK가 측정한 입력·생성·전체 토큰 수는 답변에 표시하고 기록에 보존합니다. 측정 불가 항목은 추정해서 표시하지 않습니다.

## 오프라인 준비와 아이폰 설치

1. 웹 빌드 결과 `dist/`를 **HTTPS 정적 호스팅**에 배포합니다. PC의 localhost 주소는 아이폰에서 접속할 수 있는 배포 주소가 아닙니다.
2. 아이폰 Safari에서 배포 주소를 열고 **공유 → 홈 화면에 추가 → 추가**를 선택합니다.
3. 홈 화면 앱에서 설정을 열어 **전체 오프라인 파일 준비**를 실행합니다. 기본 문서·PDF와 AI 실행 파일은 약 116MB이며, 모델은 별도입니다.
4. **Gemma 4 E2B 다운로드 받기**를 누릅니다. 약 2.01GB의 공식 웹 모델을 자동으로 내려받고 크기·SHA-256을 검증합니다. AI 실행 파일도 함께 준비합니다. 모델 바이너리는 Git에 포함하지 않습니다.
5. 다운로드 뒤 **AI 자동 준비 중 → AI 사용 가능**으로 전환됩니다. 실행 버튼을 누를 필요가 없고, 앱을 다시 열 때도 자동으로 준비합니다. 준비 중에 질문하면 준비가 끝난 뒤 답변을 생성합니다. 모델 로드와 GPU 준비 시간은 기기에 따라 필요합니다.
6. Wi-Fi·모바일 데이터를 차단하고 재실행해 검색·AI·PDF·기록을 각각 확인합니다. 영구 저장 요청이 허용되어도 사이트 데이터 삭제나 OS 정리로 파일이 사라질 수 있습니다.

모델 정보는 `src/ai/catalog.ts`에 고정했습니다. [공식 모델](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/blob/b3ca0d2f076785a8f4b2219ddbd2bdb99954eae1/gemma-4-E2B-it-web.litertlm)의 리비전은 `b3ca0d2f076785a8f4b2219ddbd2bdb99954eae1`, 크기는 `2,008,432,640`바이트, SHA-256은 `3a08e8d94e23b814ae5414469c370c503813949acb8ceaa17e4ebf8a35af35b5`입니다. 2026-10-14 공식 API 메타데이터와 HEAD 응답(HTTP 200, CORS 허용)을 확인했습니다. LiteRT-LM 0.18.0의 웹 모델을 선택했으며 Android용 모델을 혼용하지 않습니다. **실제 아이폰에서 추론은 검증하지 않았습니다.**

## 작업 요청·감독관 점검 시나리오

작업 전 점검 화면을 사용자가 제공한 시나리오에 맞게 확장했습니다.

1. 작업자: 이름, 현장, 작업 위치와 내용으로 점검 요청.
2. 감독관: 가스·보호구·통신·환기·작업자 상태 5항목, 측정 장비/시각, 감시인/연락 방법, 투입 확인 유효기한 기록.
3. 감독관: 점검 저장 후 승인 또는 보완 요청. 미확인 항목·측정값 누락·문서 기준 밖 값으로 승인할 수 없습니다.
4. 작업자: 승인 내용 확인 후 현장 투입 기록. 유효기한이 지나면 투입 확인이 차단됩니다.
5. 웹은 AI가 실제 초기화된 기기에서 문서 지원 모드로 전환합니다. 앱에 포함된 점검 화면은 네이티브 모델 설치 상태를 확인하고 질문 버튼으로 앱 AI 화면을 엽니다. 모델 설치와 실행 중 상태를 구분합니다.
6. 실시간 가스 모니터링은 Android 측정기 연계가 필요하다고 표시합니다. 센서 미연결 값은 `—`입니다.
7. 직접 확인한 위험 상황의 수동 신고와 대피 시작 기록.
8. 작업자 탈출/퇴장 위치 확인 후 감독관이 종료를 기록.

상태 전환마다 담당자·역할·시각을 남기고, 승인과 점검 저장 당시의 측정·점검 내용도 사건 기록에 보존합니다. 동시에 같은 버전을 수정하면 한 번만 반영됩니다. 기존 단순 점검 기록은 그대로 조회할 수 있습니다. 상세 설계와 현재 권한 범위는 [작업 흐름 안내](docs/workflow.md)를 참고하세요.

처음 접속한 기기는 **작업자**입니다. 점검·설정의 **감독관 화면으로 전환**은 오늘의 숫자 6자리 입력 화면을 엽니다. 코드를 모르는 작업자는 감독관 화면을 볼 수 없으며 주소 직접 입력·역할 값 변조·승인 API 호출도 서버 인증 없이 허용하지 않습니다. 서버 관리자가 코드를 감독관에게만 별도로 전달합니다.

```powershell
# web 폴더에서 서버 관리자만 실행
npm.cmd run supervisor -- today
# 오늘 코드 교체 / 코드와 기존 인증 권한 중지
npm.cmd run supervisor -- rotate
npm.cmd run supervisor -- revoke
```

오늘 코드는 여러 감독관이 반복 사용할 수 있고 코드와 권한은 **한국 시간 다음 날 00:00**에 만료됩니다. 잠금은 해당 기기만 해제하며 당일 코드로 다시 인증할 수 있습니다. `rotate`는 기존 코드·권한을 모두 무효화하고 다른 6자리로 교체합니다. 코드는 서버 비밀키로 계산하며 원문을 DB·프런트엔드·Git에 넣지 않습니다. DB와 `.local/workflow.sqlite.daily-key`를 함께 보존해야 서버 이전 후 당일 코드가 유지됩니다. 공유 코드를 전달받은 사람도 인증할 수 있으므로 유출 시 교체합니다. 브라우저 기기별 세션으로 동작하며 개인 계정 로그인·현장별 배정·계정 복구는 아직 제공하지 않습니다. 등록된 감독관은 이 서버 프로젝트의 전체 작업을 점검합니다.

Node.js **24.15 이상**에서 `npm run dev`와 `npm run preview`가 작업 API도 함께 실행합니다. 작업 기록·권한은 Git에서 제외된 `.local/workflow.sqlite`에 저장하며 같은 서버에 연결한 PC·탭이 공유합니다. 작업자는 본인 요청만 확인하고 다른 기기의 변경은 최대 15초 간격으로 확인합니다. 푸시 알림은 없습니다. 새 점검 기능에는 서버 연결이 필요하고 문서·PDF·AI는 준비 후 오프라인으로 사용합니다. 이전 로컬 작업은 읽기 전용으로 보존합니다.

`dist` 정적 파일만으로 감독관 인증·점검 API를 제공할 수 없습니다. 외부 운영에는 HTTPS와 별도 API 런타임/DB 보관·백업 구성이 필요하며 이번 작업에서 배포하지 않았습니다. 상세 범위는 [작업 흐름 안내](docs/workflow.md)에 있습니다.

## HTTPS 배포

아래는 문서·AI 정적 파일 배포 설정입니다. 작업 요청·감독관 인증에는 같은 사이트의 `/api/` 런타임과 영속 DB가 추가로 필요합니다. 정적 호스트의 빌드 명령은 `cd web && npm ci && npm run build`, 게시 디렉터리는 `web/dist`입니다. 전체 디렉터리를 배포해야 오프라인 리소스가 함께 제공됩니다. `public/_headers`는 Netlify/Cloudflare Pages 형식의 헤더 예시이며 다른 호스트에는 아래 설정을 직접 적용합니다.

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
X-Content-Type-Options: nosniff
```

`index.html`, `sw.js`, `asset-manifest.json`은 `Cache-Control: no-cache`로 제공합니다. JS/CSS 해시 파일은 내용이 바뀌면 파일명도 바뀝니다. WASM은 `application/wasm`, JS 모듈은 JavaScript MIME으로 제공해야 합니다. 해시 라우팅을 사용해 정적 호스트의 개별 화면 경로 설정이 필요 없습니다. 이 작업에서는 외부 호스팅을 생성하거나 배포하지 않았습니다.

## 데이터와 버전

`npm run prepare:assets`는 기존 Android 자산에서 JSON/PDF를 복사하고 설치된 npm 패키지에서 런타임·폰트 등을 수집합니다. SHA-256·크기를 기록한 `public/asset-manifest.json`과 설치 아이콘을 생성합니다. 생성물은 Git에서 제외하며 재현 가능한 `package-lock.json`을 포함합니다. Android 자산 폴더는 읽기만 합니다.

| 경로 | 역할 |
| --- | --- |
| `src/features/` | PDF·설정 화면 |
| `src/App.tsx` | 홈·질문·보관함·기록·점검 및 탐색 |
| `src/rag/` | 검색·질문 분해·원문 답변·간단한 답변 검증 |
| `src/ai/` | 모델 파일 저장 및 LiteRT-LM 추론 |
| `src/chat/` | 사용자 스크롤 보존·프레임 단위 자동 이동 |
| `src/storage/` | IndexedDB 기기 기록·설정·이전 작업 이력 |
| `src/workflow/` | 공통 작업 전환·서버 세션/API 클라이언트 |
| `server/` | 감독관 인증·SQLite 작업 API·코드 발급/회수 CLI |
| `src/offline/` | 파일 검증·캐시·준비 상태 |
| `scripts/` | Android 자산 복사·PWA 빌드·검색 평가 |
| `tests/` | 검색·기록·모델 무결성·마크다운·서비스 워커 회귀 |

현재 고정된 주요 버전은 React 19.2.0, Vite 8.3.4, TypeScript 5.9.3, PDF.js 6.4.299, LiteRT-LM 0.18.0입니다. 세부 버전은 lockfile을 따릅니다.

현재 자동 테스트는 **18개 파일 126개 통과**입니다. 서버 권한·일일 공유 코드·한국 자정 만료/교체/중지·CSRF·소유권·동시 갱신·재시작 보존도 검사합니다. 검색·저장소·모델 무결성에 더해 작업 상태 전환, 승인 조건, 담당 작업자 구분, 유효기한, 동시 갱신, 사건 당시 측정값 보존과 자동 다운로드 호출을 검사합니다. 자동 초기화 중복 방지·준비 중 질문 대기·취소 후 복구·토큰 설정 저장과 SDK 전달·사용량 측정·준비 중 설정 변경, 수동 스크롤 유지·자동 이동 재개·완료 후 위치 유지도 검사합니다. 현행 구조는 [웹 설계서](../docs/webapp/TARGET_ARCHITECTURE.md), 작업자/감독관은 [작업 흐름](docs/workflow.md), 향후 수정 기준은 [유지보수 안내](../docs/webapp/BUILD_PROMPT.md)에 정리했습니다. `docs/webapp-ui/` 및 2026-10-07 서버 RAG 제안은 이전 시안/계획으로 보존합니다.
