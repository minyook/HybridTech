검증일: 2026-10-14, 스크롤 재개 동작 추가 검증: 2026-10-15. Windows 개발 환경이며 실제 iPhone 검증 기록은 아닙니다.

## 자동 검증

- `npm.cmd run build`: TypeScript 검사, Vite 프로덕션 빌드, PDF 판본 해시 확인, PWA 파일 목록 생성 성공.
- `npm.cmd test`: 15개 파일, **100개 테스트 통과**.
- 검색·복합 질문·문서 밖 질문·원문 페이지 연결, IndexedDB 저장/복원/삭제, 모델 크기·해시·중단 처리, Markdown 구조·HTML/이미지 처리·수치 범위 보존, 서비스 워커 오프라인 응답 및 `Vary: Origin`, 손상된 다운로드와 캐시 복구를 검사했습니다.
- 작업 요청·승인·투입·대피·종료의 상태 전환, 요청한 작업자 구분, 측정값 경계와 누락·유효기한, 동시 갱신 충돌, 점검 당시 데이터 보존, 고정된 공식 모델 다운로드와 브라우저 fetch 호출을 추가 검사했습니다.
- 자동 AI 준비 중복 방지, 준비 중 질문 대기, 취소 후 다음 질문 복구, 실패 재시도, 출력 한도 변경 시 엔진 재사용, 문맥 변경 시 재초기화, 초기화 도중 설정 변경, 토큰 설정 저장/복원/범위, 실제 SDK 옵션과 측정값 전달을 검사했습니다.
- 스크롤 회귀 19개: 기존 위치 보존·예약 취소·복귀 검사와 함께 생성 끝부분으로 내려올 때 페이지 끝 이전 자동 재개, 위로 탐색 중 재개 금지, 창 크기 변경만으로 재개 금지, 완료 답변의 자유 탐색, 입력창·헤더·키보드 가림 영역, 아래 방향 입력, 같은 위치 이벤트가 겹칠 때 재개 유지 여부를 검사합니다.
- `node scripts/evaluate.mjs`: **29/30**. 상세 결과는 [evaluation-results.json](evaluation-results.json)에 있습니다. 생성 답변 정확도 평가는 포함하지 않습니다.
- 의존성 설치 마지막 감사 결과: 알려진 취약점 0건.

## 남은 검증

- HTTPS 실제 호스팅과 iPhone 홈 화면 설치.
- Gemma 생성 답변 검토와 완전 오프라인 재실행. Windows 내장 Chromium에서 바이너리 자동 다운로드·검증·저장·초기화는 확인했습니다.
- 기종·iOS/Safari 버전별 저장소 유지, 앱 종료/재부팅, 메모리·발열·성능.
- AI 생성 답변의 수치·단위·조건 대조 및 전문 검토.

기존 Android PDF 번들·음성 수정 사항은 웹 작업 시작 전부터 있던 변경이며 내용을 확인하고 함께 보존합니다. 최종 `git diff --check`를 통과했습니다. 웹 작업은 Android 화면·센서 동작을 재설계하지 않았습니다.

## 동반 Android 변경 확인

공식 PDF 2종을 assets에 포함하고 해시/쪽수를 검사하는 경로, 기기 내 음성 인식이 없을 때 외부 음성 입력으로 전환하지 않는 기존 변경을 함께 정리했습니다. `:app:testDebugUnitTest :app:assembleDebug`가 성공했습니다(단위 테스트 태스크는 유효한 기존 결과를 재사용). `SourcePdfRepositoryTest` 계측 테스트는 소스에 포함하며 이번 요청에서 연결 단말 실행은 하지 않았습니다. iPhone·실측 장비 시험 결과와 구분합니다.

## 2026-10-15 작업자·감독관 접근 분리

- 작업자 화면의 감독관 전환 버튼을 제거했습니다. 기존 `work-views`의 역할 값은 읽지 않으며 이름만 이전합니다. 미인증 감독관 주소에는 코드 입력 화면을 표시합니다.
- 서버 CLI 일회용 코드(24시간), HttpOnly 기기 세션, 감독관 권한 8시간, 잠금·관리자 회수·5회 실패 제한·CSRF 검사를 구현했습니다. 코드·세션은 원본 대신 해시로 저장하고 API는 no-store로 제공합니다.
- 신규 작업은 서버 SQLite에서 요청자와 역할을 검사합니다. 다른 기기의 본인 요청 노출/수정, 역할·담당자 ID·감독관 이름 위조, 감독관 작업 API 직접 호출을 거부합니다. 같은 서버의 인증된 감독관은 PC·탭 등 다른 기기 요청을 조회·승인할 수 있습니다. 푸시는 구현하지 않았습니다.
- API HTTP 회귀 15개, 이전 로컬 이력 보존·기존 상태 전환·서비스 워커 API 제외를 포함한 관련 4개 파일 **37개 통과**. 전체 **15개 파일 100개 테스트 통과**, TypeScript와 프로덕션 빌드 성공.
- 서버 재시작 후 작업 소유권·코드 사용 여부·회수 유지, 동일 버전 동시 변경 1회 반영을 검증했습니다. 개발 서버에서 `/.local/workflow.sqlite`, 해당 절대 경로의 `/@fs/` 접근, `/server/store.ts`가 모두 HTTP 403으로 차단됨을 확인했습니다.
- 내장 Chromium에서 기본 작업자의 감독관 메뉴 없음 → 감독관 주소 직접 입력 시 인증 화면 → 잘못된 코드 거부 → 유효한 코드 등록 → 가상 점검/승인 → 작업자 투입/정상 퇴장 → 감독관 종료 → 잠금 시 감독관 메뉴 사라짐 → 감독관 주소 재접속 차단을 확인했습니다. 테스트 코드와 SQLite DB는 Git에 포함하지 않습니다.
- 화면: [미인증 접근 차단](screenshots/supervisor-access-locked.jpg), [인증 후 감독관 승인](screenshots/supervisor-authenticated.jpg). 모두 가상 작업·가상 측정값으로 확인했습니다. 갤럭시 탭 하드웨어에서 이 인증 흐름 전체를 직접 조작한 시험은 아닙니다.

새 작업·점검·승인·투입/퇴장 기록에는 서버 연결이 필요합니다. 이전 로컬 테스트 작업은 읽기 전용이며 서버 승인으로 취급하지 않습니다. 문서·PDF·AI는 기존 오프라인 경로를 유지합니다. 현재 권한은 기기 세션 단위이며 개인 계정 로그인·현장 배정·계정 복구·외부 운영 배포는 남아 있습니다. 배포에서 정적 `dist`만 올리면 감독관/작업 API를 사용할 수 없습니다.
