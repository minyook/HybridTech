# 작업 요청부터 퇴장까지

최종 갱신: 2026-10-15. 사용자가 제공한 ‘온디바이스 AI 에이전트 기반 복합가스감지기 시스템’ 그림의 작업 흐름과 서버 감독관 인증을 구현했습니다.

## 작업자와 감독관의 접근 구분

작업자와 감독관이 같은 `WorkOrder`를 확인합니다. 작업자는 요청·보완·투입·위험 신고·퇴장, 감독관은 점검·보완 요구·승인·승인 취소·종료 확인을 기록합니다. 모든 작업은 문서 검색·AI 설정과 같은 PWA 안에서 이어집니다.

처음 접속한 브라우저는 작업자로 시작하고 본인이 요청한 작업만 조회합니다. 작업 전 점검·설정의 ‘감독관 화면으로 전환’은 **암호코드 입력 화면**으로 이동합니다. 오늘의 숫자 6자리를 서버에서 확인해야 감독관 메뉴·점검·승인 화면이 열립니다. `#/supervisor` 주소를 직접 입력해도 미인증이면 입력 화면만 표시합니다. 이전 IndexedDB의 `work-views.view`나 클라이언트가 보낸 역할·담당자 ID는 권한 근거로 사용하지 않습니다.

코드는 서버에서만 발급하며 소스나 프런트엔드 환경변수에 기본 코드를 넣지 않습니다. 명령은 `web/`에서 실행합니다.

```powershell
npm.cmd run supervisor -- today
npm.cmd run supervisor -- rotate
npm.cmd run supervisor -- revoke
```

`today`는 한국 날짜 기준 오늘의 코드를 확인하며 반복 실행해도 바뀌지 않습니다. 감독관에게만 따로 전달하고 여러 감독관이 같은 날 같은 코드로 인증합니다. 코드와 인증 권한은 **다음 날 00:00(한국 시간)**에 함께 만료됩니다. 5회 실패한 기기와 같은 접속에서 누적 30회 실패한 인증은 각각 15분 제한합니다. ‘감독관 화면 잠그기’는 해당 기기 권한만 제거하고 세션을 교체하며, 같은 날 유효한 코드로 다시 인증할 수 있습니다. `rotate`는 오늘 코드를 교체하고 이전 코드의 모든 권한을 무효화합니다. `revoke`는 오늘 코드와 해당 권한을 중지하며 `rotate`로 재개합니다. 다음 날짜에는 새 코드가 자동 생성됩니다.

세션은 HttpOnly·SameSite=Strict 쿠키로 관리하고 변경 요청에는 CSRF 토큰을 검사합니다. HTTPS로 직접 실행할 때 Secure 쿠키를 사용합니다. 모든 작업 조회·상태 전환에서 서버가 역할과 요청자 소유권을 다시 확인합니다. 세션 토큰은 SHA-256 해시로 저장합니다. 일일 코드는 별도 비밀키와 날짜·교체 세대로 HMAC을 계산하며 코드 원문을 DB나 프런트엔드에 저장하지 않습니다. API 응답은 no-store이고 서비스 워커 캐시에 넣지 않습니다. 현재는 개인 계정 로그인이 아닌 **브라우저 기기별 인증**입니다. 쿠키를 지우거나 다른 브라우저를 쓰면 별도 작업자로 인식합니다. 등록된 감독관의 조회 범위는 이 서버 프로젝트의 전체 작업이며 현장별 배정·계정 복구는 후속 영역입니다. 공유 코드가 전달되면 그 사람도 인증할 수 있으므로 유출 시 즉시 교체합니다.

개발/미리보기 서버가 `/api/`와 SQLite를 함께 실행합니다. 새 작업·사건 기록과 권한은 Git에서 제외한 `web/.local/workflow.sqlite`에 보관합니다. PC·탭 등 같은 서버를 사용하는 기기는 서버 기록을 공유하며 화면 진입/포커스와 15초 간격으로 작업을 확인합니다. 별도 푸시 알림은 없습니다. 5174 개발 화면과 4173 미리보기는 같은 서버 DB를 사용합니다.

작업 요청·조회·점검·승인·투입/퇴장 기록은 서버 연결이 필요하며 서버 미연결 시 감독관 화면은 닫힙니다. 문서·PDF·기기 내 AI의 오프라인 동작은 유지됩니다. 이전 로컬 테스트 작업은 기기에서 읽기 전용 이력으로 보존하고 서버 승인으로 가져오지 않습니다. 설정 내보내기는 로컬 이력과 조회 가능한 본인 서버 작업을 JSON v3에 구분하고, 서버 미연결 시 누락 상태를 명시합니다. 기기 기록 삭제는 서버 작업을 지우지 않습니다.

작업자 권한으로 승인하거나, 다른 작업자의 요청을 조회/수정하거나, 퇴장 확인 없이 종료하는 요청은 서버가 거부합니다. 감독관 사건에는 서버가 부여한 기기별 이름과 ID를 기록합니다. 공유 코드 방식이므로 개인 신원 확인을 의미하지 않습니다.

## 감독관 점검

그림의 5항목(가스·개인보호구·통신·환기·작업자 상태)을 사용합니다. 가스값은 실제 장비에서 확인해 수동으로 기록하는 방식이며 실시간 센서값과 구분합니다. O₂/CO₂는 %, H₂S/CO는 ppm입니다.

문서와 [산업안전보건기준에 관한 규칙 제618조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028062345)에 명시된 공기 기준을 대조합니다. 값 누락·음수·NaN·무한대·문서 기준 이탈, 5항목 미확인, 장비/출처·측정 시각·감시인·연락 방법 누락, 승인 유효기한 미설정 시 승인을 거부합니다. 이 검사는 실제 현장 적합성이나 작업허가를 자동 인증하지 않습니다.

승인한 점검은 투입 전 작업자가 원래 측정값·장비·감시인·연락 방법·메모를 읽을 수 있습니다. 승인 취소 후 재점검하더라도 이전 승인 당시의 점검 데이터는 사건 목록에 보존합니다. SQLite 트랜잭션과 revision으로 중복·동시 갱신을 방지합니다. IndexedDB 스키마는 v2를 유지하며 기존 대화·모델·로컬 점검 기록을 보존합니다.

## 그림과 현재 구현의 차이

- 음성 작업 지시는 현재 텍스트 요청입니다.
- AI 모드는 Gemma 문서 지원입니다. 가스 예측 모델이나 ‘1~2분 전 예측’을 구현했다고 표시하지 않습니다.
- 실제 BLE 측정·현장 경보는 기존 Android 측정 경로에 남습니다. 웹은 미수신 가스값을 표시하지 않습니다.
- 긴급 탈출 안내는 사용자가 직접 기록한 상황과 위치입니다. 검증된 대피 경로나 거리를 생성하지 않습니다.
- 같은 서버의 다른 기기 요청 조회·승인은 지원하지만 푸시 알림은 연결 전입니다.

## 실행과 후속 운영 범위

Node.js 24.15 이상 환경에서 `npm run dev` 또는 `npm run build` 후 `npm run preview`로 실행합니다. 코드 확인·교체는 서버 PC의 CLI에서만 수행합니다. `.local/`은 정적 파일 접근과 Git에서 제외합니다. 다른 서버로 옮길 때는 서버를 중지한 뒤 DB와 `workflow.sqlite.daily-key`를 함께 백업해야 같은 날짜의 코드가 유지됩니다. 모델·대화는 기기에 유지됩니다.

## Android 앱과 같은 화면 사용

설치형 앱도 현재 웹의 홈·문서 카드·설정·내비게이션 디자인을 기준으로 맞춥니다. `FieldWorkspaceUi.kt`가 Compose 공통 화면을, `NativeWorkPage.kt`가 작업 전 점검·감독관 화면을 담당합니다. 앱 설정에서 같은 작업 서버 주소를 저장하면 WebView가 이 웹 화면과 API를 사용합니다. 앱의 문서 질문·LiteRT-LM·BLE·음성·위젯은 네이티브 경로입니다. WebView는 웹 AI를 중복 초기화하지 않고 질문/모델 준비 버튼은 앱 화면으로 이동합니다. 네이티브 모델의 설치 상태와 실제 엔진 실행 상태를 구분합니다.

운영 주소는 HTTPS를 사용합니다. 디버그 빌드는 USB 포트 연결을 통한 `http://localhost:4173`도 허용합니다. 검증된 같은 서버 origin의 탐색만 허용하고 임의 자바스크립트 브리지는 추가하지 않습니다. 앱 WebView와 외부 브라우저는 쿠키가 서로 달라 각각 인증해야 합니다.

현재 API는 Vite 개발·미리보기용입니다. `dist`만 정적 호스팅하면 문서·AI는 사용할 수 있지만 점검/감독관 기능은 열리지 않습니다. 외부 운영 배포에는 HTTPS와 API 런타임·영속 DB 백업·프록시의 안전한 쿠키 전달, 개인 로그인·현장 배정·계정 복구·푸시 정책을 추가해야 합니다. 인터넷 공개나 실운영 배포는 수행하지 않았습니다.

권한 회수·코드 재발급·서버 재시작 후 보존, 작업자 소유권과 감독관 승인 우회 거부를 실제 HTTP API 테스트로 검증합니다. 실제 센서나 작업허가를 자동 인증하는 시스템으로 간주하지 않습니다.
