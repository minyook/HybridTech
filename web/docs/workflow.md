# 작업 요청부터 퇴장까지

2026-10-14. 사용자가 제공한 ‘온디바이스 AI 에이전트 기반 복합가스감지기 시스템’ 그림을 바탕으로 기존 웹 점검을 확장했습니다.

## 같은 사이트의 두 화면

작업자와 감독관이 같은 `WorkOrder`를 확인합니다. 작업자는 요청·보완·투입·위험 신고·퇴장, 감독관은 점검·보완 요구·승인·승인 취소·종료 확인을 기록합니다. 모든 작업은 문서 검색·AI 설정과 같은 PWA 안에서 이어집니다.

현재 화면의 역할 선택은 **로컬 시나리오 검증용**입니다. 다른 기기의 사람에게 요청을 전달하거나 실제 감독관 계정 권한을 부여하지 않습니다. 브라우저 내 IndexedDB를 사용하며 같은 origin의 탭에는 변경 사실을 BroadcastChannel로 전달합니다. 원격 알림이나 푸시 전송은 없습니다.

## 상태와 전환

| 현재 상태 | 가능한 다음 동작 | 담당 화면 |
| --- | --- | --- |
| 작업 요청 | 점검 저장 / 보완 요청 | 감독관 |
| 점검 중 | 점검 수정 / 승인 / 보완 요청 | 감독관 |
| 보완 요청 | 보완 내용 작성 후 재요청 | 요청한 작업자 |
| 승인 기록 | 현장 투입 확인 | 요청한 작업자 |
| 승인 기록 | 승인 취소 및 재점검 | 감독관 |
| 현장 투입 | 실제 AI 문서 지원 모드 전환 | 요청한 작업자 |
| 현장 투입 / 문서 지원 | 수동 위험 신고 | 작업자 또는 감독관 |
| 현장 투입 / 문서 지원 | 정상 작업 종료 후 퇴장 확인 | 요청한 작업자 |
| 대피 중 | 실제 탈출 후 집결 위치 확인 | 요청한 작업자 |
| 퇴장 / 탈출 확인 | 인원·기록 확인 후 종료 기록 | 감독관 |

작업자 자신이 승인하거나, 다른 작업자가 투입을 기록하거나, 퇴장 확인 없이 종료하는 전환을 도메인 함수가 거부합니다. 이 구분은 시나리오 로직의 검사이며 서버 인증을 대신하지 않습니다.

## 감독관 점검

그림의 5항목(가스·개인보호구·통신·환기·작업자 상태)을 사용합니다. 가스값은 실제 장비에서 확인해 수동으로 기록하는 방식이며 실시간 센서값과 구분합니다. O₂/CO₂는 %, H₂S/CO는 ppm입니다.

문서와 [산업안전보건기준에 관한 규칙 제618조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028062345)에 명시된 공기 기준을 대조합니다. 값 누락·음수·NaN·무한대·문서 기준 이탈, 5항목 미확인, 장비/출처·측정 시각·감시인·연락 방법 누락, 승인 유효기한 미설정 시 승인을 거부합니다. 이 검사는 실제 현장 적합성이나 작업허가를 자동 인증하지 않습니다.

승인한 점검은 투입 전 작업자가 원래 측정값·장비·감시인·연락 방법·메모를 읽을 수 있습니다. 승인 취소 후 재점검하더라도 이전 승인 당시의 점검 데이터는 사건 목록에 보존합니다. IndexedDB의 readwrite 트랜잭션과 revision으로 중복·동시 갱신을 방지합니다. IndexedDB 스키마는 v2이며 기존 대화·모델·단순 점검 저장소를 보존합니다.

## 그림과 현재 구현의 차이

- 음성 작업 지시는 현재 텍스트 요청입니다.
- AI 모드는 Gemma 문서 지원입니다. 가스 예측 모델이나 ‘1~2분 전 예측’을 구현했다고 표시하지 않습니다.
- 실제 BLE 측정·현장 경보는 기존 Android 측정 경로에 남습니다. 웹은 미수신 가스값을 표시하지 않습니다.
- 긴급 탈출 안내는 사용자가 직접 기록한 상황과 위치입니다. 검증된 대피 경로나 거리를 생성하지 않습니다.
- 감독관의 다른 기기 알림과 원격 승인은 서버 연결 전입니다.

## 감독관 코드 방식에 대한 제안 — 아직 구현하지 않음

사이트를 분리하지 않고 공통 화면의 설정에서 ‘감독관 등록’을 여는 구성이 적절합니다. 일반 사용자는 작업자 권한으로 시작하고, 별도로 전달한 **개인별·현장별 일회용 초대코드**를 자신의 로그인 계정에 등록해 감독관 권한을 얻는 방식을 제안합니다. 공용 고정 암호는 공유·유출 시 누가 권한을 얻었는지 추적하거나 개인만 회수하기 어렵습니다.

코드에 만료·사용 횟수·실패 횟수 제한과 권한 회수를 두고, 해당 감독관에게 배정된 현장·작업만 접근하게 해야 합니다. 코드를 프런트엔드 번들·localStorage에 넣거나 버튼을 숨기는 것만으로 승인 권한을 보호해서는 안 됩니다. 서버가 로그인 계정과 현장 소속을 기준으로 **모든 조회·승인 요청**의 권한을 검사해야 합니다. [OWASP 권한 검증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)을 근거로 한 설계 제안입니다.

오프라인 문서·AI와 달리 다른 기기 감독관의 승인 수신에는 통신이 필요합니다. 서버 확인이 안 된 승인은 ‘승인 대기’로 남기고 실제 승인 완료와 구분해야 합니다. 로그인·초대코드·현장 배정·서버 동기화 방식은 사용자 결정 후 구현할 영역입니다.
